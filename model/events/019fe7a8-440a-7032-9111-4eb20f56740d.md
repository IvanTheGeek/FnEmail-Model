## Data

**No data.** The method sanctions this: *"If an event has no meaningful payload beyond its identity (e.g., a simple state transition), it is fine to have no fields or just the identity key."* It also warns, of a different case, that *"An event without fields is an opaque label"* — both are recorded here rather than reconciled, because reconciling them is a later step's work, not Brain Storming's.

## Where RFC 5321 says so

## Notes

RECOVERED BY THE RE-SWEEP because the chapter roster names 'existing trace preserved' as a topic and no inherited candidate carried it. Doubtful for a reason worth recording rather than resolving: the compliant arm of a MUST NOT is normally a non-event, and idx 196's author said exactly that and declined to name it. Kept anyway because the RFC states preservation *positively* at §2.3.10 810-813 — a relay transmits 'without modification to the message data other than adding trace information' — which is a description of something a relay did, not merely of something it refrained from. THE FIELDLESS TENSION, RECORDED NOT RESOLVED, as the brief requires: one field, the identity key, is all this event honestly has, and the kit says both 'it is fine to have no fields or just the identity key' and 'An event without fields is an opaque label'. Both are true here at once — the label is opaque, and padding it with a preserved-line count would manufacture a computed field to hide that. Opposite: ReceivedLineChainAltered. FnEmail screens: the consumer test / G1 decisively, and the condemned status/phase register, which would read this as a status assertion rather than a change. ⚠️ FIELD HYGIENE PASS: THE TENSION ABOVE IS NOW RESOLVED IN ONE DIRECTION AND THIS EVENT IS FIELDLESS. The single field it had was `message_ref`, and that key does not exist — RFC 5321 supplies no message, session, transaction or connection identifier anywhere, so 'just the identity key' was never available to this event; it was holding a fabrication. What identifies the occurrence is the message's own preserved chain, read at the next hop. The earlier author's instinct that padding it with a preserved-line count would manufacture a computed field was right and is now doubly right, since such a count is exactly what rule 4 of this pass strikes elsewhere in the chapter. This is the one fieldless event in the chapter and the method sanctions the outcome explicitly; the confidence stays doubtful for the reason already recorded — a compliant non-act — not because of the strike.
