## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §4.4 | 3240-3243 | *"The primary purpose of the Return-path is to designate the address to which messages indicating non-delivery or other mail system failures are to be sent. For this to be unambiguous, exactly one return path SHOULD be present when the message is delivered."* |
| §4.4 | 3229-3231 | *"any further (forwarding, gateway, or relay) systems MAY remove the return path and rebuild the MAIL command as needed to ensure that exactly one such line appears in a delivered message."* |
| §4.4 | 3258-3260 | *"The reverse-path address (as copied into the Return-path) MUST be used as the target of any mail containing delivery error messages."* |

Line numbers are into [`docs/rfc/rfc5321.txt`](../../docs/rfc/rfc5321.txt), the archived copy. Quotations keep the specification's own words and spellings (AGENTS.md rule 2).

## Notes

RECOVERED BY THE RE-SWEEP as the violated arm of the SHOULD at 3242-3243. The inherited set noted the asymmetry inside idx 199's notes and never made the failure state an event. It earns its own row because of the collision with 3258-3260: the reverse-path copied into the Return-path MUST be used as the target of every delivery error message, and with two of them present there is no single answer to a MUST — a mandatory rule made unsatisfiable by a merely recommended one. That is a genuine 🟥 and it is the sharpest thing in the Return-Path cluster. Real data per rule 8 makes it visible: \<Smith@bar.com> from the originator and \<announce-owner@foo.com> from a list expansion both surviving to the same delivered message, and a bounce having to pick. Causes: ReturnPathSubmittedByOriginatingSystem, ReturnPathInsertedByOutboundGateway. Remedies the spec offers, both permissive: ReturnPathRemovedInTransit, ReturnPathHeaderStrippedBeforeDelivery. FnEmail screens: the responsibility-boundary cutoff and the consumer test. ⚠️ FIELD HYGIENE PASS: struck the fabricated `message_ref` identity key — RFC 5321 supplies no message identifier, and f2C8D14 is this project's own minted value. Identity is the set of competing paths, which is what the ambiguity consists of. Also corrected the return_paths example under rule 8: it was a one-element list on an event defined by there being more than one, so the payload contradicted the meaning; the two values are now the exact pair the inherited note already argued for in prose, with their sourcing split honestly — the list-owner address is invented, as the RFC supplies none.
