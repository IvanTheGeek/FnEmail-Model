## Notes

RECOVERED BY THE RE-SWEEP — §2.3.5's syntax restriction produced no inherited candidate at all. Strength: none. It is stated as a flat restriction ('are restricted for SMTP purposes'), not with an RFC 2119 keyword, and no behavior on violation is given anywhere: 🟥. It belongs in this chapter rather than a syntax chapter because the consequence is a resolution consequence — a non-LDH label is what will not resolve. The example uses an underscore, which is legal in DNS generally and not here; that mismatch is the realistic failure. Sibling: LocalAliasAppearedInTransaction (well-formed but unqualified) — the two failures are independent and a name can have both. Opposite arm has no event: a conforming label is a non-act. Which project screen would have killed it: the four altitude tiers, and the twelve-slice model has nowhere to put it. ⚠️ FIELD HYGIENE PASS: struck offending_label as a derived value — it is the offered_name split on dots and tested against the LDH rule at 700-702, which is exactly the computation the method sends to a read model. Identity here is the name offered, within the transaction that offered it; RFC 5321 supplies no transaction identifier, so position in the session is what locates the occurrence. The surviving example remains illustrative: RFC 5321 gives no non-conforming label anywhere, which is why rule 8's real-value discipline had nothing to draw on.
