## Notes

Carried from the inherited candidate. Strength: MUST. This is the strongest candidate in the chapter for an event that is genuinely not derivable — a preference sort is recomputable from the records and is therefore set aside as a computed value, while a random draw is not recomputable and so the drawn order is a fact. That pair is the cleanest illustration in the whole span of where the kit's no-computed-fields rule actually cuts: it saves this event and kills its neighbor. The precondition 'there is no clear reason to favor one (e.g., by recognition of an easily reached address)' is an unnamed judgment with no criteria: 🟥, and it is also the escape hatch that makes the opposite arm hard to call a violation. Opposite event carried: EqualPreferenceRandomizationSkipped. Wording note for anyone tiering this: 'Lower numbers are more preferred than higher ones'. Rejected alternative names: MxTieBroken, LoadSpreadAcrossExchangers, EqualPreferenceOrderDrawn. ⚠️ FIELD HYGIENE PASS: nothing struck; no fabricated identity key was present, and the inherited notes had already applied the no-computed-fields test to this event's neighbor. preference is kept as part of the identity — it names WHICH tie was broken when a domain has several preference levels — and is not itself the sort. Its example is labeled illustrative because RFC 5321 gives no preference numbers anywhere; D.3 at 4995-4997 says only 'best preference' and 'a lower preference'. drawn_order is illustrative for the same reason the RFC supplies no multi-exchanger zone.
