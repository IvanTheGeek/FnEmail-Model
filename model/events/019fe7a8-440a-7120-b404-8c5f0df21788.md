## Notes

Strength: SHOULD, conditional on "if supplied by the foreign environment". The capped sweep carried the whole fallback ladder inside one return_path_source field; the re-sweep SPLITS the last rung out as ReturnPathDefaultedToOriginatorAddress, because the condition differs (an address was supplied, versus none was) and because the second rung carries the chapter's third lowercase near-miss keyword. This card is now the first rung only: an error return address existed and was used. Whatever lands here becomes the mandatory target of every later delivery error under the §4.4 MUST, so a wrong value silently sends bounces nowhere. Rejected alternative names: ReturnPathAdoptedFromForeignEnvironment, EnvelopeReturnPathEstablishedInbound. Distinct from ReversePathConstructedFromForeignEnvelope (§4.4 lines 3268-3273), which is the header-derived construction; this one is the foreign envelope's own error address. Which project screen would have killed it: inbound-only scope.

FIELD HYGIENE PASS: struck message_ref (example f2C8D14) — RFC 5321 supplies no message identifier, and on this event the return path being set IS the identity-bearing fact for everything downstream, since the §4.4 MUST at 3258-3260 makes it the target of every later delivery error. Corrected return_path, which read \<Jones@foo.com>: that is the walk scene's recipient, and a reverse-path example that is a forward path inverts the distinction. Set to the walk scene's reverse-path \<Smith@bar.com>, with the caveat recorded here that the walk scene has no foreign-side address at all — the Internet-side sender stands in, and a facilitator walking this path for real will need to mint one.
