# `MessageContentPassedThroughUnmodified`

A relay handed the message on with its header section and body exactly as received, having added nothing but its own trace line.

## Data

**No data.** The method sanctions this: *"If an event has no meaningful payload beyond its identity (e.g., a simple state transition), it is fine to have no fields or just the identity key."* It also warns, of a different case, that *"An event without fields is an opaque label"* — both are recorded here rather than reconciled, because reconciling them is a later step's work, not Brain Storming's.

## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §3.6.3 | 1524-1527 | *"a relay SMTP has no need to inspect or act upon the header section or body of the message data and MUST NOT do so except to add its own "Received:" header field (Section 4.4)"* |
| §3.6.3 | 1528-1529 | *"Of course, this prohibition also applies to any modifications of these header fields or text (see also Section 7.9)."* |
| §2.3.10 | 811-814 | *"receives mail from an SMTP client and transmits it, without modification to the message data other than adding trace information, to another SMTP server for further relaying or for delivery."* |

Line numbers are into [`docs/rfc/rfc5321.txt`](../../docs/rfc/rfc5321.txt), the archived copy. Quotations keep the specification's own words and spellings (AGENTS.md rule 2).

## Notes

RECOVERED BY THE RE-SWEEP, and named directly in this chapter's charter ('content left untouched'). The inherited set carried only MessageDataModifiedByRelay, the violated arm; the honored arm - the content surviving the hop intact - was missing entirely, which is the shape of what the schema cap cut. Strength: MUST NOT with two named carve-outs, so 'untouched' means untouched EXCEPT for the Received: line and, optionally, loop inspection. 2.3.10's definition (811-814) makes the same point positively and is what makes this an event rather than an absence: a relay is DEFINED as the thing that transmits without modification. Honest counter-argument recorded, not resolved: nothing happened to the content, so this may be a non-event in the way 'the guest did not book' is a non-event. Rejected names: MessageRelayedIntact, ContentPreservedAcrossHop, MessageDataLeftUntouched. --- FIELD HYGIENE - NOW FIELDLESS. Struck added_header_field: 'Received:' is invariant here, since the 1526 carve-out permits exactly one addition, so it is the event and not a field. Struck queue_id (stream root is Message, not Queue Entry; f2C8D14 is this project's minted value and nothing in the content-integrity fact needs it) and relay_host. Fieldlessness sharpens the counter-argument already recorded rather than hiding it.
