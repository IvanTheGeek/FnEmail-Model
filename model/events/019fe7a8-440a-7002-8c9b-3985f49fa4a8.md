## Notes

Split out of the inherited LocalAliasRejected under the merge rule 'a refusal is not an acceptance' — here, a refusal is not the violation. Doubtful because §2.3.5 does NOT license it: the prohibition binds the client, and no reply code appears anywhere in the span, so both the existence and the shape of the refusal are 🟥. Note also the sharper 🟥 the inherited notes found: 714-718 require names be *resolvable*, which makes conformance depend on live DNS state, so two byte-identical sessions a week apart can differ in conformance. No field carries a reply code precisely because none is licensed — padding it with 501 or 550 would be inventing the spec. Sibling: LocalAliasAppearedInTransaction (the violation this responds to). Which project screen would have killed it: the consumer test, since nothing in the current model consumes it. ⚠️ FIELD HYGIENE PASS: struck two of three fields. session_id went because RFC 5321 supplies no session identifier at all; while a session lives, the channel is its identity, and that is what identifies this refusal. refusing_host went as padding — it restated the actor slot ('SMTP server') at instance level and added no fact. The event now carries one field, which is the method's sanctioned 'identity key plus nothing' shape and is the right outcome for an event whose entire content is that a name was refused. The inherited discipline on reply_code was already correct and is left standing: none is licensed, so none is invented.
