# `ReversePathRebuiltForOnwardHop`

A forwarding or gateway system reconstructed the MAIL command's reverse-path for the next hop rather than passing the original through, changing where errors will be sent.

## Notes

Carried over from idx 202, renamed from MailCommandRebuilt — the old name described the mechanism, not the state change, and 'rebuilt the MAIL command' says nothing about what changed. Rejected alternative names: MailCommandRebuilt, ReversePathRewrittenForRelay. Split from ReturnPathRemovedInTransit deliberately: 3288-3290 makes the rewrite the *defining* difference between forwarding and aliasing, so fusing them would lose the one fact that distinguishes the two mechanisms. Real values are the mailing-list case the span itself raises at 3217-3219, walked per rule 8: a message from \<Smith@bar.com> expanded by a list acquires \<announce-owner@foo.com> as its backward-pointing address, and that substitution is the entire point. AMBIGUITY WORTH RECORDING: 'this subsection' at 3289 is unresolvable — the identical sentence appears at §3.9.2 lines 1728-1730 where it refers to list redistribution, and here it lands inside Trace Information; §3.4 is separately titled 'Forwarding for Address Correction or Updating'. Read it as forwarding-as-opposed-to-aliasing and do not cite it for a section identity. FnEmail screens: inbound-only scope; also the two-kinds capture/decision lens, which would want this classified before it was allowed to exist. ⚠️ FIELD HYGIENE PASS: struck the fabricated `message_ref` identity key — RFC 5321 supplies no message, transaction or session identifier; the stream root reads 'Transaction' but the RFC names no transaction id either, and what carries identity is the reverse-path in the MAIL command of the onward hop. The two surviving fields are the substitution itself, which is what 3288-3290 makes definitional. Sourcing recorded honestly: \<Smith@bar.com> is the walk scene's sender, while \<announce-owner@foo.com> is invented — the RFC describes the list-owner arrangement at 3217-3219 but supplies no address for it.
