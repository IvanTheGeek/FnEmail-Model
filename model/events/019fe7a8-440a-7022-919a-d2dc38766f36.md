## Notes

MERGED from FOUR inherited candidates: three separately named MailExchangerRecordPublished (from the §1.1-§2.3.5, §3.6-§3.7 and §5-§6 sweeps) and MxRecordsPublished (Appendix D.3 sweep); a fifth, MailRoutingDnsRecordPublished (§3.5 sweep), names the same act from the mailing-list span. Rejected alternative names, all recorded so the naming research survives: MxRecordsPublished, MailRoutingDnsRecordPublished, MxRecordCreated. Strength: NONE anywhere — RFC 5321 treats MX records as ambient environment and never describes publishing one; the act lives in RFC 1035 and RFC 974, named at lines 1423-1424. This is the precondition all of §5.1 reads and the clearest over-time event in the chapter: records change and silently re-point mail, so two byte-identical sessions a week apart route differently. Without it, NoUsableMailExchangerFound and SelfIdentifiedInMailExchangerList are unreachable. ttl_seconds is kept deliberately and is not padding — it is the one fact that decides when a change becomes visible to a sender. stream_root DNS Zone is INVENTED: none of the offered roots fits, because the zone is another organization's asset and Server Configuration would wrongly imply it is ours. Siblings: MailExchangerRecordWithdrawn (carried), AliasRecordPublished (carried), AddressRecordPublished (carried). Which project screen would have killed it: all of them — another organization's system, Infrastructure altitude, no consumer in the current model, and no slice to hold it. ⚠️ FIELD HYGIENE PASS: struck ttl_seconds, against the inherited defense left standing just above. RFC 5321 never mentions a TTL or a time to live — a case-insensitive grep for both over the file returns nothing — so the field reaches past this chapter's source into RFC 1035 and the value 3600 has no source in the spec being swept. The inherited argument that it decides when a change becomes visible is real and is why the strike is recorded rather than made silently; a later step working from RFC 1035 may restore it. No fabricated identity key was present. mail_domain and exchanger_host take the RFC's own worked zone from D.3; preference stays illustrative because D.3 states only 'best preference' and 'a lower preference' and the RFC gives no number anywhere.
