## Notes

RECOVERED BY THE RE-SWEEP. idx 80's notes named LoopingMessageDiscarded and LoopingMessageReported as siblings and kept neither; §6.3 says 'rejection threshold' (4070), which means the detection is expected to be followed by a refusal, and a detection with no disposition leaves the message in the system. Rejected alternative names, kept so the research survives: LoopingMessageDiscarded, LoopingMessageReported, LoopingMessageStopped. Chosen 'Rejected' because that is the RFC's own word at 4070; 'discarded' and 'reported' are two different dispositions the RFC does not choose between, which is itself a gap — §6.2 lines 4057-4063 tell a server not to bounce hostile content but say nothing about whether a looping message earns a non-delivery notification, and sending one into a loop is how loops feed themselves. Worth a 🟥. DELIBERATE OMISSION: no reply code field, because §6.3 specifies none and 550 would be fabricated. Distinct from MailLoopDetected on the brief's own rule that a refusal is not a detection: a server can detect and pass on (LoopedMessagePassedOnUndetected covers the negligent form). FnEmail screens: the consumer test / G1 and the twelve-slice model. ⚠️ FIELD HYGIENE PASS, two strikes. `message_ref` struck: RFC 5321 supplies no message identifier and f2C8D14 is this project's minted queue id; identity is the channel and the message's own Received: chain, since the refusal is issued in-session on a message the host will not keep. `received_count` struck as a derived value for the same reason as on MailLoopDetected — a count is a fold over the lines the message carries. The event is now single-field and near-opaque, and that is reported rather than patched: its justification does not collapse, because the refusal is a real act the RFC names at 4070 and is distinct from the detection, but everything that made the payload look substantial was the count. The inherited record's refusal to invent a reply code was right and this pass confirms it — §6.3 specifies none, and rule 4 would have struck one.
