## Notes

RECOVERED BY THE RE-SWEEP. A MAY that explicitly licenses violating the intent of the specification is rare enough to be worth its own event, and no inherited candidate carried it. Strength: MUST include the mailbox (1338), MAY return free-form text instead when circumstances are exceptional (1340-1342) — the exception is stated without any test for 'exceptional', which is a genuine ambiguity the RFC leaves open and a later step will have to settle or mark. Marked doubtful because the payload is by definition unspecified: the event's one substantive field is a string with no schema, which is close to the kit's 'an event without fields is an opaque label' warning even though the field is present. Rejected alternative names: DebuggingTextReturned, NonMailboxReplyReturned, ExceptionalReplyFormUsed. Which screen would have killed it: the guest-viewed-calendar test, the consumer test, and 'one event per command'. Sibling: SourceRouteReturnedInVerificationReply — both are events about the SHAPE of a diagnostic reply rather than its answer, and both were invisible to sweeps that looked only for answers. FIELD HYGIENE PASS: nothing struck — no reply code and no invented identity key were present. What the pass adds is honesty about returned_text that was previously only implicit in the confidence: the RFC licenses the field at 1340-1342 and supplies no example of it anywhere, so the value is invented illustration and now says so. Rule 5's test — an unsourceable value signals an invented field — half-fires here: the field is genuinely licensed by the spec, only its content is ours, which is a different case from a fabricated key. Left doubtful, not downgraded further, because the licensing sentence is real and the field is the event's whole content. Identity is the query and the channel; the RFC supplies no session key.
