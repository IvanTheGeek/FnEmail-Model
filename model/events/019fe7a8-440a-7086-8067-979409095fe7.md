## Notes

Merged ConnectionClosedByServer (§3.8 sweep) and TransmissionChannelClosed (§4.2/4.3 sweep). Rejected alternative names: ConnectionClosedByServer, SessionClosed, ConnectionClosed. §3.8 licenses exactly THREE arms under normal operation — QUIT-with-221, 421 shutdown, and timeout — and §7.8's defensive close is a fourth, explicitly outside 'normal operational circumstances'. The model's existing SessionClosed{cause: quit \| timeout \| abort \| shutdown} carries an 'abort' arm §3.8 does not license and §4.1.1.10 lines 2210-2212 forbids, and lacks the defensive arm. Step 1 deliberately keeps each arm's antecedent as its own event — SessionEndRequested, ServiceUnavailableAnnounced, ServerInactivityTimeoutExpired, ConnectionClosedDefensively — because collapsing them into one enum is a later step's job; whether close_arm belongs on this event at all is already live in the model, where SessionClosed.cause is flagged unconsumed on the direct walk. The kit's fieldless permission applies — a bare SessionClosed would be legitimate — but it would then be an opaque label, and closed_by with preceding_command is exactly what separates the graceful close from the unilateral one. Note §4.3.2 lists QUIT with a success reply and NO error replies at all, though lines 3056-3058 say any command can return 500, 501 or 421: the QUIT row is incomplete on its face. FIELD HYGIENE PASS: struck 3 fields. session_id struck: no such key in the spec. peer_address struck: the peer belongs to the channel and was recorded at TransmissionChannelOpened. close_arm struck as a derived classification — its value is decided entirely by which antecedent event preceded this one, and the note above already says that collapsing the four antecedents into one enum is a later step's job; the model's own SessionClosed.cause is flagged unconsumed for the same reason. closed_by and preceding_command survive as the raw facts the classification would have been folded from.
