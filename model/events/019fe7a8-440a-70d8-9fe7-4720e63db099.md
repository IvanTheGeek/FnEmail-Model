# `MailCommandRejectedForUninitializedSession`

A MAIL command arrived on a session that had never been initialized by EHLO, so no transaction could begin.

**No data.** The method sanctions this: *"If an event has no meaningful payload beyond its identity (e.g., a simple state transition), it is fine to have no fields or just the identity key."* It also warns, of a different case, that *"An event without fields is an opaque label"* — both are recorded here rather than reconciled, because reconciling them is a later step's work, not Brain Storming's.

## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §4.1.4 | 2448-2451 | *"A session that will contain mail transactions MUST first be initialized by the use of the EHLO command. An SMTP server SHOULD accept commands for non-mail transactions (e.g., VRFY or EXPN) without this initialization."* |
| §4.1.4 | 2490-2494 | *"The NOOP, HELP, EXPN, VRFY, and RSET commands can be used at any time during a session, or without previously initializing a session. SMTP servers SHOULD process these normally (that is, not return a 503 code) even if no EHLO command has yet been received; clients SHOULD open a session with EHLO before sending these commands."* |

Line numbers are into [`docs/rfc/rfc5321.txt`](../../docs/rfc/rfc5321.txt), the archived copy. Quotations keep the specification's own words and spellings (AGENTS.md rule 2).

## Notes

RECOVERED BY THE RE-SWEEP of §4.1.4, the chapter's own anchor — no sweep produced an event for the opening MUST of the section. The pairing at 2490-2494 is what makes this event precise rather than vague: it names the five commands that explicitly do NOT draw a 503 without EHLO, so the refusal is scoped to transaction commands, and it is the RFC itself that names 503 as the code NOT to use for those five, which is the only reason 503 is the natural guess here. ⚠️ INFERENCE, FLAGGED: no code is stated for the MAIL-without-EHLO case. Note the asymmetry in strength — MUST on initializing, SHOULD on accepting the non-mail commands without it. Distinguish from NestedMailCommandRejected (a transaction is open) and from CommandRejectedAsOutOfSequence (the umbrella). Rejected alternative names: TransactionAttemptedBeforeGreeting, MailBeforeEhloRejected. Screens: the twelve-slice model always greets first, so this state is unreachable inside it.

FIELD HYGIENE PASS: struck two fields, leaving the event FIELDLESS. session_id (f2C8D14) goes because RFC 5321 supplies no session identifier and f2C8D14 appears nowhere in the document — it is this project's own minted queue-id example from commit 6acfc68. The strike is pointed here: the event's content is that the session was never INITIALIZED, and a session identifier would have implied a named session existing before EHLO, which is precisely what the RFC declines to give — the channel is the session's identity from the moment it opens, and what EHLO adds is initialization, not a name. reply_code (503) struck as unsourced and as rendering: the note above already flags that no code is stated for this case, and its own reasoning shows why the guess is fragile — 2490-2494 names 503 as the code NOT to use for five other commands, which is an argument by contrast, not a statement. Fieldless is correct: nothing distinguishes one instance of this refusal from another except where in the session it occurred.
