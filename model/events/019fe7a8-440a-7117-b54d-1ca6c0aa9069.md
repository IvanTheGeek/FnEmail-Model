## Notes

RECOVERED BY THE RE-SWEEP. The violated arm of the MUST at 1577-1578; no sweep carried it, which is the pattern the brief predicted — capped sweeps keep the honored arm and drop the violated one. It matters concretely rather than formally: §6.3 lines 4067-4069 makes loop detection a count of Received: fields, so a gateway that skips its line makes a looping message look younger than it is, and Appendix B lines 4779-4786 says loops through the gateway boundary are the common case. Opposite event: ReceivedLinePrependedByGateway. Sibling under the same MUST NOT arm: ExistingReceivedLineAlteredByGateway. Observability caveat worth recording rather than resolving: an omission produces no record at the gateway, so it is only ever detected downstream — the kit's line that "An event without fields is an opaque label" bites here, and padding it with fields it does not have would be worse. Which project screen would have killed it: inbound-only scope, and the consumer test / G1, which would ask what reads a non-stamping.

FIELD HYGIENE PASS: struck message_ref (example f2C8D14). The original note already warned against padding this event, and then carried a fabricated identity key anyway — the warning and the defect sat in the same record. RFC 5321 supplies no message identifier; an omission is identified by the gateway that failed to stamp and by the direction of the crossing the MUST is conditioned on (line 1577). Both survivors are sourced. Note the irony the strike sharpens: this event's whole consequence is that nothing downstream can attribute the crossing, which is exactly why no key exists to record.
