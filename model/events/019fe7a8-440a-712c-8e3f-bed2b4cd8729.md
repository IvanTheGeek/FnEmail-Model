# `ReturnPathRewrittenToListAdministrator`

The envelope return address was changed to the address of the list's administrator, so every later error message for this copy goes to the list rather than to the original sender.

## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §3.9 | 1690-1693 | *"When a message is delivered or forwarded to each address of an expanded list form, the return address in the envelope ("MAIL FROM:") MUST be changed to be the address of a person or other entity who administers the list."* |
| §3.9.2 | 1723-1727 | *"The return (backward-pointing) address in the envelope is changed so that all error messages generated by the final deliveries will be returned to a list administrator, not to the message originator, who generally has no control over the contents of the list and will typically find error messages annoying."* |

Line numbers are into [`docs/rfc/rfc5321.txt`](../../docs/rfc/rfc5321.txt), the archived copy. Quotations keep the specification's own words and spellings (AGENTS.md rule 2).

## Notes

Renamed from the inherited ReturnPathRewritten to disambiguate it from the gateway and relay rewrites in chapters 9 and 8; rejected alternative names: ReturnPathRewritten, BackwardPointingAddressChanged, ReversePathRetargeted, MailFromReplacedWithListOwner. Strength: MUST (line 1692). It sits in a paragraph with a second MUST pulling the opposite way — the envelope MUST change and the header section MUST NOT (1694-1696) — which is the sharpest statement in the whole RFC that envelope and header are different objects, and it feeds docs/smtp-path-vs-mailbox.md directly. Both arms of that pair now have events: this one and its opposite ListReturnPathLeftUnchanged, plus HeaderSectionModifiedByExpander for the second MUST. previous_reverse_path is kept because the originator's address is genuinely lost from the envelope at this moment and survives only in the header section — it is a fact of the event, not a computed value. Screens: the responsibility-boundary cutoff (this happens after MessageAccepted); the condemned status/phase register is NOT the screen that reaches it, despite the shape. FIELD HYGIENE PASS: nothing struck. previous_reverse_path was re-tested against the method's derived-value rule and survives on the line applied across this chapter — a value the event destroys stays, a value merely carried along unchanged goes — and the earlier pass's argument for it is the right one. new_reverse_path is now labeled illustrative: grep for "owner-" over rfc5321.txt returns nothing, so the RFC supplies no example of an administrator address even though it MUSTs one into the envelope. queue_id kept on the §4.4 ID-clause warrant.
