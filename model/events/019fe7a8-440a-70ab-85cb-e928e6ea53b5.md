# `TerminatingLineEndingAdded`

An originating SMTP system added \<CRLF> to a message body whose final line lacked one, so that the receiving server could recognize the end-of-data condition.

## Notes

Harvested. Strength: MUST, with TWO arms, and this is one of them — the other is MessageRejectedAsInvalidByOriginator, recovered separately below, which is what the sweep's own notes asked a later step to do. A MUST that offers a choice of two conforming outcomes is rare enough to flag: neither arm is optional, but which one is taken is entirely the implementation's. This event also exposes a precondition nobody writes down: line 2023 says the body "were passed to the originating SMTP-sender", which is a handoff from a user agent to a submission agent — an event with no name anywhere in RFC 5321 and the actual start of the whole story (the sweeps' MessageHandedFromUserAgentToMta and MailCollectedFromUser are attempts at it, and belong to a submission chapter). Screens: the inbound-only scope and the responsibility-boundary cutoff kill it twice over, since both actor and moment are on the far side of the wire. Rejected alternative name: FinalCrlfSupplied.

FIELD HYGIENE PASS: struck one of three. submission_id is fabricated and belongs to the same family as session_id and transaction_id — RFC 5321 supplies no submission identifier, and this act happens before any SMTP session exists, so there is not even a channel to stand in for one. That absence is a real finding about the spec: nothing in RFC 5321 identifies a message before it is offered with MAIL, which is why the trace ID clause of §4.4 (rfc5321.txt:3336) is stamped by the RECEIVER and not carried from the origin. originating_host is kept, unlike the session-level host fields struck elsewhere, precisely because there is no session event to carry it here: it is the only party-identifying fact available on this side of the wire. final_line is kept as the one fact that makes the event meaningful — the line that lacked its terminator — and its value is illustrative.
