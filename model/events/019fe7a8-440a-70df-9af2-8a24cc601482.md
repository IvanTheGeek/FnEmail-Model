## Notes

Recovered by the re-sweep as the violated arm of the MUST at 3690-3692 — the honored arm is MessageQueuedForDelivery and the truncated sweeps carried only that one. This is the silent-loss case: the message is neither delivered nor bounced, so no notification ever fires and the originator learns nothing, which is exactly the failure §6.1 exists to prevent. §3.6.3 1478-1481 says clients with this limitation exist in practice, so the violated arm is not hypothetical. Rejected name: MessageDroppedInsteadOfQueued. Screens: inbound-only scope, and the consumer test G1 would kill it outright since nothing downstream reads a fact about a message that stopped existing. ⚠️ FIELD HYGIENE PASS: this event is now FIELDLESS, and the emptiness is the finding rather than a gap. STRUCK message_id — f2C8D14 is a queue id and this message was never queued, and RFC 5321 supplies no message identifier of its own; §4.4's ID clause (rfc5321.txt:3336) admits an Atom or an RFC 5322 msg-id, but both are written by a receiving server into the trace header and neither is a field the spec hands a sending client. STRUCK destination_host as derived from the forward path by address resolution, and STRUCK discarded_at as a bare occurrence time. Nothing carries identity here because nothing survived the discard to be identified — which is precisely why the MUST at 3690-3692 exists, and the empty payload states that more honestly than a fabricated key did.
