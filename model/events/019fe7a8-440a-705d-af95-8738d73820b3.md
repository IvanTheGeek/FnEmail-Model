# `MailDataTransformedForLocalStorage`

A message store converted received mail data into a local representation — different character set, record structure, or delimiter convention — under an obligation that the conversion be reversible.

## Notes

Inherited candidate 222, kept in this chapter because storage at final delivery is its remit. The MUST has an unusual shape worth flagging rather than flattening: it lands on a PROPERTY of the event, not on the event — transforming is optional, reversibility is not, so reversible: true is a conformance assertion and a store that cannot honor it is forbidden to transform at all. 'especially if they are applied to mail being relayed' does not weaken the MUST; it says where breaking it hurts most, which is why applied_to_relayed_mail is carried. The trailing arm nobody has drawn is IrreversibleTransformApplied — the violation — and it is not given its own row only because the RFC gives no way to observe it at the moment it happens; a facilitator may reasonably add it. Screens: the responsibility-boundary cutoff and the Infrastructure altitude tier; the actor does not exist in the current model. ⚠️ FIELD HYGIENE PASS 2026-08-09 — three fields struck. message_id: RFC 5321 supplies no message identifier (§4.4's ID clause at line 3336 is optional and is the receiver's trace clause; msg-id is RFC 5322's) and f2C8D14 is this project's minted queue_id value; identity here is the stored mail data itself, on the Mailbox root the store owns. reversible: struck although the inherited notes defended it — on this pass it reads as a conformance assertion rather than a fact, and the argument the notes themselves make is why: the MUST at 3454-3456 fixes the value at true for every permitted occurrence, so a recorded true carries no information, and the false case is not this event at all but IrreversibleTransformApplied, the violation arm the notes already name. applied_to_relayed_mail: struck as context derived from the message's disposition elsewhere in the model rather than a fact this event establishes — 'especially if they are applied to mail being relayed' says where breaking the MUST hurts most, which the notes preserve, and does not make relay status a payload fact of the transform. transform survives as the one thing the event actually records, and its example is now sourced to the RFC's own phrasing at line 3453.
