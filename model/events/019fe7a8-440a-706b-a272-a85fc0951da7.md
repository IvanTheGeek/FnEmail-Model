## Notes

RECOVERED BY THE RE-SWEEP. The violated arm of a MUST that RFC 5321 states twice, in both of this chapter's anchors (§4.4 3293-3294 and §6.1 3972-3973); no inherited candidate carried it. It earns a row because its consequence is structural rather than cosmetic: the null reverse-path is the ONLY thing that makes the MUST NOT at 3983-3984 fire, so a single notification sent with a real return path disarms the loop cut for every hop downstream. A spec that states one rule twice in two sections is signaling how much depends on it, and the arm where it is broken is where mail loops come from. Confidence 'likely' — the RFC states the rule, never the violation as an occurrence. Screens: the condemned status register and the capture/decision lens would refuse a violation event outright. ⚠️ FIELD HYGIENE PASS 2026-08-09 — one field struck. notification_message_id: RFC 5321 supplies no message identifier; §4.4's ID clause (line 3336) is optional, belongs to a receiver's Received: stamp, and takes an Atom or an RFC 5322 msg-id, so nothing in this document names the notification itself. f2C8D14 is this project's own minted queue_id value from commit 6acfc68. Identity here is the offending value, reverse_path_used, together with the host that sent it — and the value is the whole event, since a null path in that slot would make this the conforming case instead. The example is sourced honestly: postmaster is the RFC's reserved local-part (line 735), the domain is the walk's.
