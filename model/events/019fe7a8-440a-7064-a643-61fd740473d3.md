=== FIELD HYGIENE PASS === Struck two of three fields. (1) message_ref (f2C8D14) — same finding as on DeliveryFailedAfterAcceptance: RFC 5321 supplies no message identifier, and f2C8D14 appears nowhere in the RFC. What carries identity here instead: the set of accepted forward-paths from the mail transaction the message arrived in — which is exactly what §4.4 3285-3287 makes the notification name. (2) delivered_recipients — struck as a DERIVED value under the method's own rule: it is the accepted recipient set minus the failed set, and the accepted set is already recorded on the RCPT-acceptance events, so the difference belongs to a read model. Recorded so a facilitator can restore it: §4.4 3277-3280 does name both halves ("delivered to some, but not all"), which is an argument that both are recorded facts; the argument against is that only the failed set has a consequence in this chapter. Example sourced and corrected in kind: Brown@foo.com is ACCEPTED at RCPT in Appendix D (rfc5321.txt:4899-4900) and is therefore available to fail after acceptance, whereas Green@foo.com is refused at RCPT (rfc5321.txt:4897-4898) and would be the wrong example for a post-acceptance failure.
