# `DiagnosticCommandRejectedAsOutOfSequence`

## Notes

RECOVERED BY THE RE-SWEEP as the violated arm of the SHOULD at 2492-2493 — and the RFC is unusually explicit about which behavior it is prohibiting, naming the code inside a parenthesis: 'that is, not return a 503 code'. Strength: SHOULD not (2492), against a MUST at 2517 that requires 503 for genuinely out-of-order transaction commands. So 503 is mandatory in one case and discouraged in the neighboring one, and the distinction rests entirely on whether the command is part of a mail transaction — which is why this chapter's commands are the ones the rule is written about. The second citation also supplies the compensating fact: a 503 leaves the server's state exactly as it was, so the only thing this event changes is what the client knows. Rejected alternative names: DiagnosticCommandRefusedBeforeGreeting, PrematureCommandRejected, OutOfSequenceReplyIssued. Opposite: DiagnosticCommandAcceptedWithoutSessionInitialization. Which screen would have killed it: the consumer test (G1) — §4.1.4 says four times over that a refusal changes nothing on the server, which is the clean argument for G1 and the clean argument against it, since the state that changed is the client's. Also the HELO-only charter and 'one event per command'. FIELD HYGIENE PASS: struck two fields. session_id (f2C8D14) went as a fabricated key, and as on its opposite the point is sharper here than elsewhere: the event happens before any EHLO, so the channel and the client are the only identity there is, and RFC 5321 defines no session identifier in any case. reply_code (503) went as a wire rendering, even though the RFC is unusually pointed about this particular code, naming it inside the prohibition itself at lines 2492-2493 — 'that is, not return a 503 code'. The test is whether the spec carries the code as data beyond the wire; it does not, and the sentence that names it is quoted in the rfc_refs. One field survives. Kept at likely and not downgraded: the justification is the violated SHOULD, which the strikes do not touch, and the state change — what the client now believes about this server — does not depend on the record carrying the digits.
