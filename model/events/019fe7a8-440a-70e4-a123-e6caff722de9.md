# `DestinationBackoffWidened`

The retry cadence for a destination moved from the early frequent attempts to the longer interval used after the first hour in the queue.

## Notes

Recovered by the re-sweep. This is the chapter's named per-destination backoff topic and no inherited candidate carried it as an event — RetryScheduled's notes mentioned the schedule but only as commentary. Carries NO normative keyword at all: it is offered as experience, so an implementation that ignores the whole shape is still conforming — anyone tiering this must check the keyword, not the tone. The RFC gives a range, two or three hours, not a value, so new_interval_hours is genuinely operator-chosen. The trigger is the message's age in the queue, which makes this a second time-triggered event with no command behind it. Screens: inbound-only scope, altitude tiers, and the one-event-per-command target, which has no command to hang it on. ⚠️ FIELD HYGIENE PASS: STRUCK widened_at as a bare occurrence stamp — the age that triggers the widening is measured from MessageQueuedForDelivery.queued_at, not from this moment, so nothing keys on it. new_interval_hours stays and its example is genuinely the RFC's own: three hours is one of the two figures at 3722-3723. Both keys stay — the sentence scopes the policy to a destination and to "the message" in the queue at once, so the pair is not redundancy. queue_entry_id kept on §4.4's ID-clause ground (rfc5321.txt:3336); f2C8D14 is this project's minted value, not the RFC's.
