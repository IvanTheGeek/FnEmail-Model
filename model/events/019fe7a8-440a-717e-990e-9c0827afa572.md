## Notes

RECOVERED BY THE RE-SWEEP — it existed in the raw set only as a fold inside PostmasterAddressProvisioned's notes, which is exactly the shape truncation takes: the weaker of two facts in one sentence gets folded away. Split out because the RFC's whole point in that sentence is that the two are NOT the same state: publishing a contact point does not discharge the postmaster obligation, so a model that carries only one of them cannot represent the non-conforming site that published a contact point and never provisioned postmaster. No RFC 2119 keyword — 'some systems also identify' is descriptive. Rejected names: MailOpsContactAdvertised, ProblemContactAddressPublished. FIELD HYGIENE: struck announced_in ('connection greeting reply'). §3.1 969-971 says only that some systems identify a contact point; it never says where. The greeting placement was carried over from the software-and-version sentence three lines earlier (964-966), which is about a different fact, so the field had no source for this event. Identity is the domain; RFC 5321 supplies no session, transaction or connection key and none was present here.
