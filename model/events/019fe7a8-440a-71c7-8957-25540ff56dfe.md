# `CommandRejectedAsMalformed`

## Notes

Merged from the 501 arms of candidates 237 and 173; all citations re-checked and correct. Rejected alternative name from the merge: CommandRejectedWithStateUnchanged (candidate 173) — it fused five different faults under one reply_code field, and is split here into this event, UnknownCommandRejected, CommandRejectedAsUnimplemented, CommandRejectedAsOutOfSequence and MailParametersRejected; the invariant it was named for, that nothing on the server changes, is preserved in each meaning instead. The example is real and deliberate: mail_server.bar.com carries an underscore, which §4.1.2 forbids in a domain label, so it is the concrete case that earns the 501 rather than a placeholder. Strengths differ sharply and are a rule 3 trap: MUST for invalid character codes (2377) and MUST for a bad transaction-beginning argument (2514-2516), but only SHOULD for arguments on DATA, RSET or QUIT (3069-3070) — and even the MUST at 2377 is qualified, "this rule, like others, could be overridden by appropriate SMTP extensions". The DATA/RSET/QUIT rule is conditioned on "the absence of EHLO-advertised extensions", so it is a function of what was negotiated in this session. Also folded in: §3.3 lines 1093-1096, the spaces-around-the-colon error the RFC calls "a common source of errors" and for which it gives NO reply code at all — a real gap. Screens: the consumer test (server state unchanged by definition) and the one-event-per-command target.

FIELD HYGIENE PASS (chapter 14): session_id struck — RFC 5321 names no session, transaction or connection identifier, and f2C8D14 is nowhere in the RFC; identity here is position in the session, and the event's whole point is that server state did not move. reply_code struck: 501 is fixed by the event's meaning and is the decision rendered. received_line KEPT — the line failed to parse, so nothing else in the model captures it, and rule 8 pays off exactly here, because the underscore is the concrete fault and a placeholder would hide it.
