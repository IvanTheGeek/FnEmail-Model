## Notes

RECOVERED BY THE RE-SWEEP. The violated arm of the SHOULD at 3242-3243. The RFC is unusually explicit about the consequence in the sentence immediately before — the return path exists to designate where failure reports go, and 'For this to be unambiguous' is the clause that motivates the SHOULD — so this event is the state in which a later bounce cannot be reliably addressed. Note the strength: only a SHOULD, and 3229-3231 grants a MAY to fix it rather than a MUST, so the RFC plainly expects this state to occur and be tolerated. That combination, a known-common defect with only permissive repair, is worth a 🟥. Kept separate from ReturnPathLineOmittedAtFinalDelivery: zero return paths and two return paths are different failures with different repairs. ⚠️ FIELD HYGIENE PASS 2026-08-09 — one field struck. message_id: RFC 5321 supplies no message identifier; §4.4's ID clause (line 3336) is optional and belongs to the receiver's Received: stamp, msg-id is RFC 5322's, and f2C8D14 is this project's minted queue_id value. Identity here is the list of return paths present, which is both the payload and the defect — a List whose length is the whole finding. Note that a count would have been the obvious field here and would have been wrong twice over: computed under the method's own rule, and less informative than the values, since which paths are present is what a repair under 3229-3231 has to choose between.
