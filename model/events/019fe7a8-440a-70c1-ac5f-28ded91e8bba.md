## Notes

The MUST is on the DISTINCTION being communicated, not on any particular code — 550 and 553 are both named as normal, so reply_code is a fact with a real range, not a constant. FnEmail has ReversePathRefused, which does not distinguish permanent from temporary; rejected alternative names carried here: ReversePathRefused, SenderRejected, MailFromRejected. Kept SEPARATE from the temporary sibling on purpose — see that event's notes for why collapsing them destroys a MUST. Distinct again from TransactionCommandArgumentRejected: 550/553 judges the mailbox, 501 refuses the argument.

FIELD HYGIENE PASS: struck two fields. reply_code (550) goes as the wire rendering of a decision; the note above already establishes that the MUST at 1035-1038 is on the DISTINCTION being communicated and not on any particular code, and this chapter honors that MUST by carrying two separate events rather than one event with a code field — which is precisely why the code field was redundant. The RFC's own codes for this case are at rfc5321.txt:1045, cited above and preserved. reason_text ('sender address rejected') struck as an invented value: the phrase appears nowhere in RFC 5321, and the free text of a reply is operator-configurable rendering in any case (AGENTS rule 5 makes the same distinction on the page — the code is fixed, the text varies). No identity key was present to strike; identity is the refused reverse-path plus position in the session.
