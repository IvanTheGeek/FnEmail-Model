## Notes

Inherited candidate 201, kept. MAY, not MUST or SHOULD — permission granted precisely because the final-delivery determination at 3226-3228 is unreliable. ⚠️ It sits in direct tension with the MUST NOT at 3234-3237: a relay is forbidden to inspect the message data 'especially not to the extent needed to determine if Return-path header fields are present', yet is permitted here to remove the header it may not look for. That is a real contradiction in the text, not a reading error, and the presumable reconciliation — that a forwarder or gateway is not acting in a pure relay function — is never stated by the RFC. It earns a 🟥, and the violated arm is given its own row as RelayInspectedMessageData, below. Screens: inbound-only scope and the HELO-only charter both exclude relaying outright. ⚠️ FIELD HYGIENE PASS 2026-08-09 — one field struck. message_id: RFC 5321 supplies no message identifier — §4.4's ID clause (line 3336) is optional and is the receiver's own trace clause, msg-id is RFC 5322's — and f2C8D14 is this project's minted queue_id value from commit 6acfc68. Identity here is the removed value itself, plus the host that removed it. removing_host is marked illustrative rather than walk scene: relay.bar.com is not one of the walk's own values, and the walk has no relay in it at all.
