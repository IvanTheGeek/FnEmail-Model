## Notes

RECOVERED BY THE RE-SWEEP; it appeared in the raw set only as a named-but-not-carried sibling inside AddressVerificationDisabled's notes, which is exactly the shape truncation takes. This is the third position on a spectrum the raw set flattened to two: enabled for all, restricted to authenticated requestors, disabled entirely. The middle position matters because §7.3 4271-4273 tells sites to keep EXPN, and restriction is how a site obeys both that SHOULD and the harvesting concern at 4263-4265 at once. 'may choose' at 4270 is lowercase, not RFC 2119 — weaker than it reads. A near-sibling from another span, MailingListAccessRestricted (§3.5.1 1322-1323, the 550 Access Denied to You. example), is per-list rather than per-command and belongs to the List chapter; cross-referenced, not merged. Screens: HELO-only charter, inbound-only scope. FIELD HYGIENE: struck permitted_requestors ('authenticated requestors within foo.com'). The event name already fixes the permitted class, and §7.3 4270-4271 names exactly one — authenticated requestors — so the field restated the name with an invented site suffix bolted on; the second useful context the section mentions, 'within an administrative domain' at 4266-4267, is preserved as a citation rather than smuggled into a value. restricted_commands survives because §3.5.2's 'either or both' makes the set genuinely vary, with EXPN and VRFY both named at 4270-4271. No session, transaction or connection key was present; identity is the site named by its domain.
