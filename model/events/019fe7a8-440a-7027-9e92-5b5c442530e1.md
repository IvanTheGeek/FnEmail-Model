## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §5.1 | 3828-3829 | *"a DNS lookup MUST be performed to resolve the domain name (RFC 1035 [2])"* |
| §3.6.1 | 1433-1436 | *"There has been an invalid practice of using names that do not appear in the DNS as destination names, with the senders counting on the intermediate hosts specified in source routing to resolve any problems. | §3.6.1 | 1437-1439 | *"This is one of several reasons why SMTP clients MUST NOT generate invalid source routes or depend on serial resolution of names."* |

## Notes

RECOVERED BY THE RE-SWEEP — the violated arm of §5.1's OPENING MUST at 3828-3829, which no inherited candidate carried in either arm even though it is the first normative statement in the chapter. Strength: MUST at 3828-3829, reinforced by MUST NOT at 1437-1439 ('depend on serial resolution of names'). §3.6.1 lines 1433-1436 is what makes this a real occurrence rather than a theoretical negation: the RFC names the practice, calls it invalid, and describes senders 'counting on the intermediate hosts specified in source routing to resolve any problems'. The failure mode is DELAYED, which is what makes it worth an event of its own — nothing breaks until the source route is stripped, and that consequence is DeliveryFailedAfterSourceRouteStripped in the Relaying chapter, so the two chapters hold the two ends of one defect. delivery_domain is typed String rather than DomainName precisely because the value is a name that does not appear in the DNS. Rejected alternative names: UnresolvableDestinationNameUsed (that is the Relaying chapter's UnresolvableDestinationNameAccepted, a different actor), SerialNameResolutionDependedOn. Which project screen would have killed it: the inbound-only scope and the four altitude tiers. ⚠️ FIELD HYGIENE PASS: nothing struck; no fabricated identity key was present and no derived value. Both fields are the violation — the unresolvable name that was used and the intermediate host expected to fix it — and neither is recoverable from the other. delivery_domain keeps its illustrative label: §3.6.1 at 1433-1436 describes the practice without giving an example name, so a value had to be supplied, and the String typing is what records that it is not a domain name at all.
