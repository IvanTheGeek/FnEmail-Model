## Notes

Carried from the inherited candidate; the inherited dns_result field ('non-existent domain') is dropped as redundant with the event name, per 'do not pad events with fields just to reach a count'. Strength: MUST. The reporting act is now carried separately as RoutingErrorReported, because 'reported as an error' names no mechanism, no reply code and no audience — a 5yz reply to the peer if still in session, or a bounce if the message was already accepted, are different events with different visibility: 🟥, and this chapter's largest gap. Sibling answers from the same lookup: TargetNameResolvedToCanonicalName, MessageQueuedAfterTemporaryDnsError, ImplicitMailExchangerAssumed, NoUsableMailExchangerFound — five distinguishable answers to one query, which is why the query itself is set aside and the answers are not. Rejected alternative names: NxdomainReturned (technical rather than domain language), DestinationDomainDoesNotExist. Which project screen would have killed it: the one-event-per-command design target, which would collapse it into the RCPT rejection. ⚠️ FIELD HYGIENE PASS: struck forward_path. The lookup at 3839-3840 is per-domain, not per-recipient — several recipients can share one delivery domain and one answer — so the recipient is context a read model joins in, not a fact this event certifies. What remains is the identity key alone, which the method sanctions explicitly, and it is the right shape: the whole content of the event is already in its name. No fabricated identity key was present to strike.
