## Notes

RECOVERED BY THE RE-SWEEP. Candidate 238's notes observed that the MUST NOT at 2937-2939 implies an over-time event and named it CapabilityAdvertisementAligned, but no row was ever created — the cap took it. Recorded here as the VIOLATED arm rather than the honored one, because the honored arm (an operator keeping the advertised list consistent with the implemented command set) is a configuration non-event most of the time, while the mismatch is the fact that bites a client mid-session. The honored arm is named here so it is not lost: CapabilityAdvertisementAligned, actor Server operator, stream_root Server Configuration — add it if extension advertisement is modeled. Strength: MUST NOT, and it constrains configuration rather than any single session, which is why the stream root is not Session. Contrast with §4.1.5 lines 2540-2541, where advertising private X-commands is an explicit MAY — advertising is free, advertising what you will refuse is forbidden. Screens: the altitude tiers, the inbound-only scope, and the HELO-only charter (a HELO session has no capability list at all).

FIELD HYGIENE PASS (chapter 14): reply_code_on_use struck — it is a prediction of what the server will render if the capability is used, derived from section 4.2.4's own rule at lines 2936-2938, and a derived value belongs in a read model. advertised_keyword KEPT, with its example corrected from SMTPUTF8, which appears nowhere in RFC 5321, to 8BITMIME, which the RFC's own Appendix D session advertises at line 4889. No session key was present and none is needed: this is configuration, and its identity is the server.
