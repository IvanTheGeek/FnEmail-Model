# `ReturnPathInsertedByOutboundGateway`

A gateway carrying mail from SMTP into another transport wrote a return-path header field so that the envelope sender would survive the crossing.

## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §4.4 | 3263-3266 | *"a gateway from SMTP -> elsewhere SHOULD insert a return-path header field, unless it is known that the "elsewhere" transport also uses Internet domain addresses and maintains the envelope sender address separately."* |
| §4.4 | 3243-3246 | *"Systems using RFC 822 syntax with non-SMTP transports SHOULD designate an unambiguous address, associated with the transport envelope, to which error reports (e.g., non-delivery messages) should be sent."* |
| §4.4 | 3258-3260 | *"The reverse-path address (as copied into the Return-path) MUST be used as the target of any mail containing delivery error messages."* |
| §3.7.1 | 1556-1559 | *"Therefore, when a message leaves the Internet environment, it may be necessary to fold the SMTP envelope information into the message header section."* |
