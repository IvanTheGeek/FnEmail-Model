## Notes

Two strengths in one sentence: delaying at all is MUST (3703-3704), the 30-minute figure is SHOULD (3704-3705). Merged from RetryScheduled and DeliveryRetryScheduled — rejected name DeliveryRetryScheduled, whose actor was the accepting server discharging the second of the three obligations §4.5.2 2943-2957 attaches to a 2yz after end-of-data; that actor difference is preserved here rather than dropped, because the same state change is reached from both sides and §4.2.5 2949-2951 hands the interval rules straight to §4.5.4. The delay is scoped per DESTINATION, not per message (3703-3704) — the same insight that produces HostMarkedUnreachable. Opposite event: DestinationRetriedWithoutDelay. Dropped as derived: attempt_number. Screens: inbound-only scope, responsibility-boundary cutoff, altitude tiers. ⚠️ FIELD HYGIENE PASS: STRUCK interval_minutes — it is next_attempt_at minus DeliveryAttemptFailed.attempted_at, a computed value the method sends to a read model, and the 30-minute floor it echoed is a configured parameter already carried by RetryParametersConfigured. next_attempt_at survives because it is not an occurrence stamp at all: it is a future time and it is the whole content of the event. queue_entry_id kept on §4.4's ID-clause ground (rfc5321.txt:3336); f2C8D14 is this project's minted value, not the RFC's.
