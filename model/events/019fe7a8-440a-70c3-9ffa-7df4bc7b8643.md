## Notes

RECOVERED BY THE RE-SWEEP of §4.1.4. Two MUSTs in one sentence — the code AND the no-state-change — and the raw set had it only inside CommandRejectedWithStateUnchanged, an event that merged five different reply codes (501, 503, 555, 455, 500) whose strengths differ sharply; that merge buried this MUST among two lowercase non-keywords. Split out here. The rejected_argument example is the RFC's own named trap, made visible only by real data: `MAIL FROM: \<Smith@bar.com>` with one space after the colon is a syntax error and `MAIL FROM:\<Smith@bar.com>` is not — a placeholder would hide the entire fault. ⚠️ INFERENCE, FLAGGED: §3.3 1093-1096 names the colon-spacing error and gives NO reply code; joining it to the 501 MUST at 2514-2516 is this chapter's reading, not the RFC's statement. Rejected alternative names: CommandRejectedWithStateUnchanged, MailArgumentRejected, PathSyntaxRejected.

FIELD HYGIENE PASS: struck two fields. session_id (f2C8D14) goes because RFC 5321 supplies no session identifier and f2C8D14 appears nowhere in the document — it is this project's own minted queue-id value from commit 6acfc68; the channel carries session identity while the session lives, and this event's own placement is fixed by the command it refuses. reply_code (501) struck as the wire rendering of a decision, even though the MUST at 2514-2516 names it: a MUST about which code goes on the wire is a statement about the rendering, and the second MUST in the same sentence — that the server stays in the same state — is the one that describes the event and is preserved in the citation. rejected_argument SURVIVES and is the reason this event is worth having; its example carries the RFC's own named trap, one space after the colon, which no placeholder could show, and it is now labeled as walk-scene data with a §3.3-sourced fault rather than implied to be RFC text. command_verb survives with the real range the RFC gives at 2502-2503: MAIL, and the obsolete SEND, SOML, SAML.
