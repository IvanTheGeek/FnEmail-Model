# `SizeRestrictionImposedWithoutSizeExtension`

A server that limits message content size was configured without the SIZE service extension, so clients can only discover the limit by having a message refused.

## Notes

RECOVERED BY THE RE-SWEEP as the violated arm of the SHOULD at 3523-3525; the sweeps produced only SizeLimitConfigured, a general seven-object configuration event that belongs to the Server Configuration and Provisioning chapter and is cross-referenced rather than duplicated here. What is claimed here is the content-specific consequence: a limit with no way to announce it, which turns every oversized message into a full content transfer followed by a 552 — the transfer happens, the octets cross the wire, and only then is the message refused. That waste is the state change worth naming and it is invisible if the configuration is modeled generically. Note the lowercase "should be avoided if at all possible" at 3522 — not a 2119 SHOULD, and it applies to having a limit at all; the 2119 SHOULDs are about SIZE, on both the server side and the client side. Both client and server arms exist and only the server's is modeled here. Screens: the altitude tiers (Protocol/Infrastructure), the inbound-session scope (nothing in a session configures a limit), and the HELO-only charter, which removes SIZE from the model entirely and thereby makes this the only reachable arm. Rejected alternative names: SizeLimitConfiguredWithoutAnnouncement, UnannouncedSizeRestrictionSet.

FIELD HYGIENE PASS: struck one of three, the lightest strip in the chapter, and for a reason worth naming: this is the only event here whose stream root is not a session, a transaction or a message. It is a configuration act on a server, so the server's domain IS the stream identity rather than a session-level fact repeated per event — which is why server_host is kept where receiving_server, declining_server and rejecting_host were struck elsewhere. No fabricated key was present. size_extension_advertised is struck as a restatement: it is false on every instance of this event by definition, since the event's own name states that SIZE was not implemented, so the field carries no information about an occurrence. limit_octets survives as the substance of the configuration; its value is illustrative and labeled so, the RFC supplying only the 64K floor at rfc5321.txt:3519.
