## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §B | 4773-4777 | *"A submission protocol based on Standard RFC 822 information alone MUST NOT be used to gateway a message from a foreign (non-SMTP) mail system into an SMTP environment. Additional information to construct an envelope must come from some source in the other environment, whether supplemental header fields or the foreign system's envelope."* |
| §3.7.5 | 1633-1636 | *"Similarly, when forwarding a message from another environment into the Internet, the gateway SHOULD set the envelope return path in accordance with an error message return address, if supplied by the foreign environment."* |

## Notes

The inbound counterpart of MessageCrossedTransportEnvironmentBoundary at a lower altitude, kept because envelope_source is the fact that decides conformance under the MUST NOT at 4773-4775 — a crossing built on headers alone is the violation, and only this field distinguishes the two. Strength: MUST NOT on the forbidden derivation; note the second sentence's lowercase "must come from some source in the other environment" (line 4776), which is not the RFC 2119 keyword — a fourth lowercase near-miss in the gatewaying material. Appendix B is not one of this chapter's named anchors; it is claimed here because its subject is gatewaying inbound and no other chapter's anchors cover it. Rejected alternative names: InboundGatewayCrossingCompleted, ForeignMessageAdmittedToSmtp. Opposite event: MessageGatewayedFromHeaderFieldsAlone. Which project screen would have killed it: inbound-only scope (ironically — the project's "inbound" means inbound to a receiving server, not inbound across an environment boundary), altitude tiers.

FIELD HYGIENE PASS: struck message_ref (example f2C8D14) — RFC 5321 supplies no message identifier; a crossing into SMTP is identified by the gateway, the environment it came from, and the envelope it arrived with. envelope_source survives and is now quoted from the source: line 4777 reads "whether supplemental header fields or the foreign system's envelope". It is the one field in the record that decides conformance under the MUST NOT, so it is payload in the strictest sense. Lowercase near-miss re-verified at line 4776: "an envelope must come from some source in the other environment" — lowercase must, correctly flagged.
