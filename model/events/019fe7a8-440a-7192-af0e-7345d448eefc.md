## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §4.5.3.1.8 | 3537-3539 | *"The minimum total number of recipients that MUST be buffered is 100 recipients. Rejection of messages (for excessive recipients) with fewer than 100 RCPT commands is a violation of this specification."* |
| §4.5.3.1.8 | 3546-3550 | *"A client that needs to deliver a message containing over 100 RCPT commands SHOULD be prepared to transmit in 100-recipient "chunks" if the server declines to accept more than 100 recipients in a single message."* |

## Notes

RECOVERED BY THE RE-SWEEP — the violated arm of the §4.5.3.1.8 MUST, which the raw set carried only as a warning sentence inside RecipientLimitConfigured's notes ('any configured value below 100 is a stated violation'). Kept as its own event because the RFC does: 3538-3539 is one of very few places in RFC 5321 that names a specific configuration value as non-conforming, and a model that can only express the conforming case cannot represent the server that actually breaks interoperability. Walked with real data: at max_recipients 20, a client with 100 addresses for foo.com is refused at the twenty-first and, per 3546-3550, its 100-recipient chunking strategy does not help — the SHOULD assumes a floor of 100 that this configuration has removed. The client's mitigation is defeated by the server's violation, which is the finding, and no placeholder value would show it. Screens: all of them, plus this is exactly the shape the condemned status register rejects. FIELD HYGIENE: struck required_minimum (100). It is a constant fixed by the RFC at line 3537, identical in every instance, and the comparison that makes this event non-conforming is derived from it — the method sends such derivations to read models. The floor stays in the citation and in the walk above, where it does more work. max_recipients survives as the configured value, with its example labeled illustrative and chosen deliberately below the floor. No session, transaction or connection key was present; identity is the server named by its domain.
