## Notes

RECOVERED BY THE RE-SWEEP — no inherited candidate carried it. MUST strength, and it is a distinct capability from PostmasterMailboxProvisioned: a bare 'Postmaster' with no @domain is not a mailbox in the local-part@domain sense the rest of the spec requires, so accepting it is a separate provisioning decision about how the forward-path is parsed. Walked with real data per rule 8: RCPT TO:\<Jones@foo.com> and RCPT TO:\<postmaster@foo.com> both parse normally; RCPT TO:\<Postmaster> has no domain to route on, and that is the whole point — a client that cannot form the FQDN can still reach a human. Violated arm: a server that answers 501 to the domainless form violates an explicit MUST while satisfying the postmaster mailbox requirement, so the two events fail independently. Screens: the HELO-only charter and the one-event-per-command target. FIELD HYGIENE: struck accepted_form. The string RCPT TO:\<Postmaster> is fixed by the RFC at line 3401 and is the event's whole identity — one value, never varying — so as a field it restated the name. Kept in the meaning and in the walk above instead. Identity is the server's domain; the RFC supplies no session or connection key, and the forward-path this event is about is precisely the one with no domain in it.
