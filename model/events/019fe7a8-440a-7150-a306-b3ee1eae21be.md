## Data

**No data.** The method sanctions this: *"If an event has no meaningful payload beyond its identity (e.g., a simple state transition), it is fine to have no fields or just the identity key."* It also warns, of a different case, that *"An event without fields is an opaque label"* — both are recorded here rather than reconciled, because reconciling them is a later step's work, not Brain Storming's.

## Notes

RECOVERED BY THE RE-SWEEP. The raw candidate BounceSuppressedForHostileContent named this sibling and gave it no slot; the cap is the reason. It earns one because it is an event with a fully defined EFFECT and, by the RFC's own statement, no defined CAUSE — "a decision that is outside the scope of an SMTP server as defined in this document" (4058-4059). That is a hotspot, and it sits at the point where it bites: two events in this chapter (BounceSuppressedForHostileContent, BounceSentDespiteHostileContent) depend entirely on a determination the specification disowns. Strength: none — the RFC never requires, permits or forbids the detection; it only presupposes it, twice, at 4057-4058 and again at 4062-4063 where the passive "is determined" does the same work. Deliberately fieldless beyond identity and the determining host: the RFC supplies no criterion, no category and no evidence field, and inventing one would be padding of exactly the kind the kit warns against. Rejected alternative names: MessageJudgedHostile, HostileContentFound, ContentThreatIdentified. Which screens would have killed it: the four altitude tiers (this is not Protocol tier by the RFC's own admission), the capture/decision two-kinds lens, and the consumer test.

=== FIELD HYGIENE PASS === Struck both fields; this event is now FIELDLESS in fact, which the note above was already reaching for. (1) message_ref (f2C8D14) — fabricated; RFC 5321 supplies no message identifier. (2) determined_by — struck as a restatement of the event-level actor. WHAT CARRIES IDENTITY HERE INSTEAD: nothing at all — and that is the pointed outcome. The RFC presupposes this determination twice, at rfc5321.txt:4057-4058 (active, "is found to contain") and 4062-4063 (passive, "is determined to contain"), while disowning it in the same breath, so it supplies no criterion, no category, no evidence and no identifier. A fieldless event is the honest carrier of a determination the specification refuses to specify. CONSIDERED AND REJECTED: marking this doubtful as a field wearing an event's name — its entire content is now the string just struck from BounceSuppressedForHostileContent.rejection_reason.
