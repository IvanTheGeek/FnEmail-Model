# `MessageCrossedTransportEnvironmentBoundary`

A message left one transport service environment and entered another at an intermediate SMTP server, which is the crossing that makes every other rule in this chapter apply.

## Notes

Merged from the inherited TransportServiceTranslationPerformed; rejected alternative names carried forward from the merge: TransportServiceTranslationPerformed, MessageForwardedIntoAnotherTransportEnvironment, GatewayCrossingMade, EnvironmentBoundaryTraversed. Strength: NONE. "may require" (line 1535) is descriptive of when the situation arises, not a normative keyword; do not report it as a MAY. Kept separate from MessageTransformedByGateway even though they nearly always co-occur, because §2.3.10 lines 819-822 make the transformation conditional ("may require") on the crossing — the crossing is the fact, the transformation is a consequence that can be absent. Opposite event: a relay hop, which by §2.3.10 lines 810-814 stays inside one environment. Sibling: MessageIntroducedIntoTransportEnvironment, which is a first entry rather than a crossing and is ceded to the origination chapter. This is the event at which an SMTP-only model loses visibility: everything past it is out of the protocol. Which project screen would have killed it: the four altitude tiers (non-SMTP side is off-model), the inbound-only scope, and the responsibility-boundary cutoff. The definitional sentence at 1536-1539 is vocabulary and is set aside; only the crossing it names is kept.

FIELD HYGIENE PASS: struck message_ref (example f2C8D14). RFC 5321 supplies no message identifier that could serve as an identity key — grep for f2C8D14 over docs/rfc/rfc5321.txt returns nothing (it is this project's own minted queue_id, traceable to commit 6acfc68), and the nearest thing the spec offers is the OPTIONAL ID clause of the trace header field, ID = CFWS "ID" FWS ( Atom / msg-id ) at lines 3336-3337, which is a clause a stamping server may write into one Received: line, not a key every event carries. What identifies this crossing instead: the gateway host and the pair of environments it sits between — §3.7 lines 1533-1536 identifies a gateway by position, not by any key. gateway_host is retained as the identity substitute, not as payload.
