## Notes

RECOVERED BY THE RE-SWEEP. §7.7's second sentence names TWO acts, select and configure; the merged list carried only the configure half (AddressUpdateDisclosureRestricted). Selection is the earlier and stronger lever — a server that cannot emit 251 or 551 at all needs no configuration — and it is the only remedy available to a site whose implementation ignored §3.4's SHOULD at 1208-1211, which is why it is proposed rather than folded away. Marked DOUBTFUL and the reason named: this is a procurement decision, and its state lands in a purchasing record rather than in any mail system; the §7 sweep set aside an analogous case (IPR disclosures filed with the IETF Secretariat) on scope rather than on the read test, and the same objection applies here. Kept anyway per the kit's guidance to include when unsure and refine later, and because deleting it would leave §7.7's sentence half-modeled. Strength: lowercase "should", no 2119 keyword. Rejected alternative names: DisclosureAwareServerSelected, ServerProcuredOnPrivacyGrounds. Screens: all four altitude tiers, the inbound-only scope, and the twelve-slice model.

⚠️ FIELD HYGIENE PASS (fields and notes only): struck one field, disclosure_requirement ("must not emit 251 or 551 to clients outside bar.com") — invented outright. §7.7's whole sentence is "Sites that are concerned about those issues should ensure that they select and configure servers appropriately" at rfc5321.txt:4336-4338; it supplies no requirement language, no selection criteria and no product names, so nothing sources a value and rule 5's signal fires — the field was imagined, not observed. This is the one event in the chapter whose case is materially weakened by the strike, and it is recorded plainly rather than smoothed over: the event is called ServerChosenForDisclosureBehavior, and after stripping, no surviving field can say WHAT was chosen or ON WHAT BASIS, because RFC 5321 never names a server implementation anywhere. It is left with its identity key alone, which the method sanctions ("just the identity key"), but a later step deciding this event should weigh that its distinguishing content lived entirely in a fabricated field. Confidence was ALREADY doubtful, for the separate reason that procurement state lands in a purchasing record rather than a mail system, so it is left there rather than lowered twice — the two reasons now stack. selected_server_host kept as the Server Configuration stream's identity, sourced at rfc5321.txt:4886, the RFC's own foo.com greeting.
