## Notes

Recovered by the re-sweep. The RFC names the cycle twice — "periodically attempt" (3687-3688) and "every retry cycle" (3737-3738) — so the cycle is a first-class thing in the spec's own vocabulary even though no keyword governs it. Stream root Outbound Queue is invented: none of the offered roots covers the queue as a whole rather than one entry, and SendingSystemBlockedByRetryCycle, OutboundConcurrencyLimitReached and ErrorMessageSentInResponseToErrorMessage need the same root. Selecting which entries to attempt is a query and is in set_aside; starting the run is the write. Screens: inbound-only scope, altitude tiers (a daemon tick is Infrastructure), and the one-event-per-command target, since nothing commands this. ⚠️ FIELD HYGIENE PASS: this event is now FIELDLESS, and that is the correct outcome for a pure time-triggered transition. STRUCK started_at as a bare occurrence time — the cycle's period is a configured parameter, not a duration measured from a recorded start. STRUCK client_host: the RFC gives a host "one or more areas for queuing messages in transit" (rfc5321.txt:3673-3675), so the host does not identify a queue, and the spec names no identifier for a queue or for a queue run anywhere. Identity is carried by the daemon's own position in time, which is exactly what the stream provides.
