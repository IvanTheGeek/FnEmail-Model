## Notes

RECOVERED BY THE RE-SWEEP: §3.7.3's one-sentence cross-reference at 1600-1602 is the only place the RFC says a gateway is bound by the source-route rules, and no sweep carried it — a cross-reference sentence is exactly the kind of line a truncated pass drops, because it states no rule of its own. Strengths, three in one §3.3 sentence: MUST be prepared to encounter, SHOULD ignore, MAY decline. Values are the RFC's own worked example at §4.1.1.3 lines 1944 and 1950. Cross-reference, deliberately NOT merged: the source-route chapter owns the generic server case; this card exists because §3.7.3 extends it to an actor with different permissions — a gateway may also REWRITE the address (HeaderFieldRewrittenAtGateway), an option a plain server does not have, so the same input has more outcomes here. stream_root is Recipient rather than Message because the route belongs to one forward-path, not to the message. Which project screen would have killed it: inbound-only scope; the HELO-only charter.

FIELD HYGIENE PASS: nothing struck. This is the cleanest record in the chapter: no fabricated identity key, no f2C8D14, and both payload values taken verbatim from the RFC's own worked example — verified at line 1944 (RCPT TO:\<@hosta.int,@jkl.org:userc@d.bar.org>) and line 1950 (RCPT TO:\<userc@d.bar.org>). It is also the record that shows why the identity question has an answer here that it lacks elsewhere: on a Recipient-rooted event the forward-path IS the identity, supplied by the protocol, so no key had to be invented. Where a sweep had a real key it used one; the fabrications cluster exactly where the RFC leaves identity to the channel.
