## Notes

RECOVERED BY THE RE-SWEEP. A precondition nobody wrote down: the parenthetical exists because per-message From alteration is only safe if a stable identity exists underneath it. Strength: a LOWERCASE 'should attempt' (4193) — the 7.x span notes flag line 4193 explicitly as one of several load-bearing lowercase shoulds that read like 2119 SHOULDs and are not; 'attempt to establish' is weaker still, the obligation being to try. Rejected names: PrimaryMailboxAssigned, PermanentAddressAllocated, UserIdentityAnchored. stream_root could equally be a User root, which no offered candidate names. Screens that would have killed it: every one. FIELD HYGIENE: struck establishing_system (foo.com), an actor restatement. Corrected the surviving examples rather than merely sourcing them: user was John Q. Public while primary_mailbox was \<Jones@foo.com>, two values that cannot both be true of one person. Both now come from the RFC's own D.3 header at line 5067, From: John Q. Public \<JQP@bar.com> — real data for exactly this field pair (rule 8), the RFC's only named human with a mailbox beside Mark Crispin. No identity key was fabricated: the mailbox IS the identity, which is 4192-4196's whole point.
