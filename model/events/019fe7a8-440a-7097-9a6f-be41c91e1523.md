## Data

**No data.** The method sanctions this: *"If an event has no meaningful payload beyond its identity (e.g., a simple state transition), it is fine to have no fields or just the identity key."* It also warns, of a different case, that *"An event without fields is an opaque label"* — both are recorded here rather than reconciled, because reconciling them is a later step's work, not Brain Storming's.

## Notes

Merged from the sweeps' DataRequested; the §4.1.1.4 syntax line was added by re-sweep and verified at 2066. Near-fieldless by nature — DATA permits no parameters (§4.1.1 lines 1777-1781), so session identity plus timing is genuinely all there is, and the kit licenses that ("it is fine to have no fields or just the identity key") while warning that "An event without fields is an opaque label" — both apply here at once and are recorded, not resolved. Rejected alternative names: DataCommandIssued, ContentTransferRequested, MailDataTransferRequested. Strength: none — §3.3 describes the step, it does not command it. The parenthesis at 1098-1099, "or some alternative specified in a service extension", matters: BDAT/CHUNKING means DATA is not the only entry into content transfer, which a single-DATA-path model hides completely. Opposite/sibling events: MailDataTransferAuthorized (granted) and DataCommandRejectedOutOfSequence (refused). No project screen kills it; FnEmail already carries DataRequested (commit f48ce92).

FIELD HYGIENE PASS: struck all three fields. session_id and transaction_id are fabricated — grep -niE "session (id\|identifier)\|transaction (id\|identifier)\|connection (id\|identifier)" over docs/rfc/rfc5321.txt returns nothing, so RFC 5321 supplies no such key; while the session lives the channel itself is the identity, and position in the session fixes this event exactly (one DATA per transaction, one transaction at a time). requested_at is struck as derived: it restates the event's own occurrence time, which every event carries by construction. The example value f2C8D14 appears nowhere in the RFC (grep returns nothing) — it is this project's own minted queue-id example, commit 6acfc68, doing duty as a session key. The result vindicates the note above rather than damaging it: the sweep already said this event is near-fieldless by nature, and with the invented keys gone it is fieldless, which the method sanctions explicitly.
