## Notes

RECOVERED BY THE RE-SWEEP as the honored arm of the §3.5.2 SHOULD; the raw set carried only the disabling arms. MERGE: absorbs ExpnServiceExtensionRegistered (rejected name, and rightly marked doubtful by its sweep — 'EXPN entered the set of extensions the server is obliged to advertise' is this same moment described by its consequence, and the EHLO listing itself is a display of configuration state that the guest-viewed-calendar test sends to set_aside). The asymmetry at 1366-1369 is the content worth preserving and survives either way: EXPN enabled MUST appear in EHLO, VRFY MAY appear, and clients need not check for VRFY at all — so the advertised keyword list is not a complete statement of what the server accepts. A separate VrfyAdvertisedAsConvenience was considered for the VRFY MAY and folded here rather than padding the count. Screens: the HELO-only charter kills it outright, since EHLO extensions are out of charter by definition. FIELD HYGIENE: struck ehlo_keyword ('EXPN') — a constant that the event name already states, since this event exists only for EXPN; the MUST to list that keyword is a consequence for every later EHLO response, and it is carried in the meaning and the citations rather than as a field the RFC never varies.
