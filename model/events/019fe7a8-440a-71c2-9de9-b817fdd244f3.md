# `MailTransactionTerminatedOnInvalidReply`

A client received a reply whose code was outside the permitted range, treated it as fatal, and abandoned the mail transaction.

## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §4.2 | 2628-2639 | *"In the absence of extensions negotiated with the client, SMTP servers MUST NOT send reply codes whose first digits are other than 2, 3, 4, or 5."* |
| §4.2 | 2639-2640 | *"Clients that receive such out-of-range codes SHOULD normally treat them as fatal errors and terminate the mail transaction."* |
| §4.3.2 | 3044-3047 | *"SMTP servers MUST NOT transmit reply codes to an SMTP client that are other than three digits or that do not start in a digit between 2 and 5 inclusive."* |

## Notes

Inherited from candidate 227; its citations checked and correct — note that the 2628-2639 range legitimately spans a page break (the sentence resumes with "or 5." at 2639 after the running header), which looks like a citation error and is not. MERGED IN by the re-sweep: OutOfRangeReplyCodeTransmitted, the server-side violation arm of the same wire fact, folded here rather than given its own row for budget; the two are genuinely different state changes with different actors and should be split if peer conformance is modeled. Note the double hedge on the client arm — SHOULD plus "normally" — the weakest obligation in the chapter; an implementation that soldiers on is arguably conforming. The server-side MUST NOT is conditional twice over: "In the absence of extensions negotiated with the client" at 2628 and "Unless extended using the mechanisms described in Section 2.2" at 3044, so a negotiated extension can make a 6yz legal. offending_reply_code is typed Text, not ReplyCode, on purpose: the whole point is that it fails the ReplyCode rule. Screens: inbound-only scope (client actor).

FIELD HYGIENE PASS (chapter 14): three fields struck plus the session key. session_id struck — RFC 5321 names no session, transaction or connection identifier, and f2C8D14 is nowhere in the RFC; identity here is the transaction, opened by MAIL and abandoned at this point. commands_completed struck as a derived fold over the session's accepted commands — read-model material by the method's own rule. terminated_at struck: it is the event's own occurrence time, which every event has, and RFC 5321 names no timestamp on a client's abandonment, so the walk scene's 1998 value was carrying nothing. offending_reply_code KEPT, and lines 2637-2640 are what make it data — servers MUST NOT send codes whose first digit is other than 2, 3, 4 or 5, and "Clients that receive such out-of-range codes SHOULD normally treat them as fatal errors" — the out-of-range code is the input the client acts on, not a decision the client rendered.
