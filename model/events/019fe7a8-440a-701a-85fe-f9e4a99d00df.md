## Notes

RECOVERED BY THE RE-SWEEP — the violated arm of the SHOULD floor at 3878, which no inherited candidate carried in either arm. Its interest is that the SAME SENTENCE PAIR permits it: the MAY at 3876-3877 licenses a configurable limit with no stated minimum, and the SHOULD at 3878 then sets a floor of two. Three lines apart, pointing opposite ways — 🟥, and the clearest instance in this chapter of a requirement that cannot be checked without deciding which clause wins. Distinct from AlternateAddressLimitReached, which fires at any configured ceiling; this one fires only below the recommended floor, and the two coincide exactly when the limit is 1. Rejected alternative names: SingleAddressPolicyApplied (neutral framing that hides the SHOULD), MinimumAddressAttemptsNotMet. Which project screen would have killed it: the inbound-only scope. ⚠️ FIELD HYGIENE PASS: struck message_id (example \<f2C8D14@foo.com>). RFC 5321 supplies no message identifier — §4.4's ID clause is optional and is the receiving host's trace entry (3329, 3336-3337), §6.4 line 4131 permits an originating server to add a message-id 'when none appears', proving one need not exist, and f2C8D14 appears nowhere in the RFC. No queue_id was substituted: the RFC defines no queue entry and no key for one, so identity is the queue entry itself. The two surviving fields are the SHOULD violation in full — one address tried, others available — and both take walk-scene values.
