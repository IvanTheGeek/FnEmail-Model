## Notes

RECOVERED BY THE RE-SWEEP. The inherited candidate AmbiguousMailboxAlternativesDisclosed modeled only the disclosing arm of the MAY at line 1240 and said in its own notes that the non-disclosing arm 'changes nothing outside the session' — that is wrong on the re-read: line 1260-1261 says the client would be expected to expose the 553 to the user, so the requester's world does change, it just changes by less. Both arms of the MAY now stand, which is the instruction applied literally. Strength: MAY, two arms (1240). Sibling and opposite: AmbiguousMailboxAlternativesDisclosed is the same MAY chosen the other way. Rejected alternative names: AmbiguityNoted, VrfyAmbiguityReported, UserAmbiguousReported. Which screen would have killed it: the 'one event per command' design target — VRFY would then own exactly one outcome event — and the consumer test. Fieldless-event tension: this event is close to the kit's 'opaque label' case; the two fields it carries are the identity of the question asked and the code that answered it, and no more were added, per 'Do not pad events with fields just to reach a count.' Reply-text convention: lines 1261-1264 recommend using exactly the given forms and the 'user ambiguous' or 'ambiguous' keywords, possibly supplemented by RFC 3463 extended reply codes, to help automated translation — a formatting concern, not a second event. FIELD HYGIENE PASS: struck reply_code (553), which resolves the fieldless tension the note above raised — one of its two fields was the code, and a reply code is the wire rendering of a decision. The exemption was tested rather than waived: RFC 5321 nowhere carries a reply code as data beyond the wire, §4.2.5 lines 2941-2965 being the closest the spec comes, and it assigns responsibility rather than persisting a code. The 553 survives in the meaning and in the rfc_refs, where line 1244 shows it. No invented identity key was present; identity is the name asked about plus position in the session, the channel being the only session handle the RFC supplies. On the surviving value: the RFC never shows the VRFY argument that produced its own ambiguous example, only the three Smiths in the reply, so 'Smith' is inferred rather than quoted and is now labeled that way.
