## Notes

RECOVERED BY THE RE-SWEEP. No inherited candidate covered HELP at all; the §4.1 sweep set it aside as a display and the cap left no room to reconsider. It is kept here for one reason: §7.5 treats HELP output as an information-disclosure event on the same footing as the greeting banner, which means the RFC itself regards the sending as consequential, not merely as a display. Strength: MAY on the argument form (2154); the reply codes are 211 and 214 (3145) with 502 and 504 as errors (3146). §4.2.2 line 2796 says the 214 reply 'is useful only to the human user', which is the strongest possible statement that nothing in the protocol consumes it — the consumer test (G1) would kill this event on that line alone, and that is precisely the screen this chapter is instructed not to apply. §4.1.1.8 lines 2157-2159 also state that HELP has no effect on the reverse-path, forward-path or mail data buffers, the RFC's own disqualifier, recorded here rather than acted on. Rejected alternative names: HelpRequested (rejected — names the command, not the completed change), HelpDisplayed, ServerHelpReturned. Marked doubtful for all of the above. Sibling: HelpRequestRefused. Note that HELP is advertised as an EHLO keyword in every one of the RFC's four scenarios — D.1 line 4892, D.2 4943, D.3 5007, D.4 5112 — even though it is a base command. FIELD HYGIENE PASS: struck two fields. session_id (f2C8D14) went first and is the chapter's canonical case: a grep over rfc5321.txt for a session, transaction or connection identifier returns nothing, so RFC 5321 supplies no such key, and a grep for f2C8D14 returns nothing either — it is this project's own minted queue-id example, and a HELP reply has no queue and no message. What carries identity instead is the channel: while the session lives, the open connection is its identity, and this event's place in it is its position in the command sequence. reply_code (214) went as a wire rendering. help_text is kept because §7.5 treats the HELP output as the disclosure — the content is the event — but its value is now labeled invented, since the RFC shows no HELP reply anywhere and the command list is borrowed from §4.5.1. Left doubtful.
