## Notes

Borderline against the kit's guest-viewed-calendar test and deliberately NOT set aside. The verb in the RFC is 'read', which reads like a query, but what changes is the client's own state: it now knows this destination is down, and its queue behavior changes accordingly. Kept apart from ServiceUnavailableAnnounced rather than merged, because the RFC's own parenthetical separates them in time — the client will not see the notice until it issues its next command, so the send and the receipt are genuinely distinct moments, and a client that never sends another command never receives it at all. received_after_command carries the mismatch: the reply does not answer the command it arrives on. stream_root is Next-Hop Destination rather than Session because what the client durably learns is about the host, not about this connection — it governs every queued message for foo.com. Screens: the inbound-only scope kills the whole client lane.
