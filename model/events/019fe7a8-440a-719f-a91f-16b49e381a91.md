## Notes

Merged from #75, #145 (3.3) and #171 (4.1.1.3); rejected names: RelayingDeclined, RecipientRejectedForPolicy, RelayAccessDenied, RelayRefused. CITATION TRAP, verified by opening the file: the 550 sentence is split across a page break - it begins 'If it declines to' at the end of 1454, the footer and running header occupy 1455-1462, and it resumes at 1463. A naive grep reports a wrong range. Strength: SHOULD on the 550, not MUST; refusal for a NON-policy reason carries no specified code at all, a genuine ambiguity. Sweep #145 flagged its own 550 as a guess from 3.3, where no code is given. Sibling: RelayDeclinedWithNonStandardCode. Wider: MailRejectedForPolicyReason (7.9). Precondition: RelayPolicyConfigured. --- FIELD HYGIENE: struck reply_code (550 is the wire rendering of this decision - 1463 governs what is SENT, and nothing in RFC 5321 carries a reply code as data beyond the wire), reason ('policy' was tautological: the section's condition IS 'for policy reasons', so the field could take no other value), and relay_host (recorder's own domain). No identity key existed to strike; identity is the refused forward-path within the open channel. Value re-based on Appendix D.3 (5060).
