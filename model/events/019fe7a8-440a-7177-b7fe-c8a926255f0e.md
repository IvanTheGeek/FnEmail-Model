## Notes

Inherited (candidate 297, renamed from GreetingDisclosureConfigured because §7.5 governs the HELP response and the greeting equally and the old name hid half its scope). Citations verified: line 4304 does end with 'implementations SHOULD minimally' and the quote is completed here across 4303-4306. An unusual SHOULD — a SHOULD to DISCLOSE, not to withhold — and the RFC's reasoning is contested enough to be worth preserving: hiding known vulnerabilities is not securing the server (4300-4303). Real wire data for the greeting varies across the RFC's own scenarios: 'foo.com Simple Mail Transfer Service Ready' at D.1 line 4886 and 'xyz.com is on the air' at D.3 line 5057, operator-configurable text in the same slot. Rejected alternative names: GreetingDisclosureConfigured (the original), HelpDisclosureScopeConfigured (the other half, equally partial), ServerVersionAnnouncementPolicySet. Overlap acknowledged: the greeting half of this event belongs as much to a Session Initiation chapter as here; it is claimed here because §7.5 is reached through HELP and the two halves cannot be separated without losing the SHOULD. Reading the banner or the help output is a display and is set aside. Which screen would have killed it: the altitude tiers (Infrastructure) and the consumer test. FIELD HYGIENE PASS: no field struck, but one VALUE corrected. greeting_text carried the reply code as a prefix — '220 foo.com Simple Mail Transfer Service Ready' — and the 220 is the wire rendering of the decision to accept the connection, not part of the configured text; this repository's own convention already draws that line, marking what the protocol fixes apart from what the operator varies. The value is trimmed to the operator-configurable part and sourced to line 4886, where the RFC's full line stays quoted in the rfc_refs so nothing is lost. version_disclosed was tested against the bar on derived values and kept: §7.5 lines 4303-4306 make disclosure a policy the site sets, an unusual SHOULD to disclose rather than to withhold, so the Boolean is a decision and not a computation. No invented identity key was present; server_host is the stream's identity on a Server Configuration root. The RFC's other greeting, 'xyz.com is on the air' at line 5057, remains the evidence that this slot genuinely varies.
