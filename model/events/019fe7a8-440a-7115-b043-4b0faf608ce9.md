## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §3.7.1 | 1559-1563 | *"A possible solution would be to create new header fields to carry the envelope information (e.g., "X-SMTP-MAIL:" and "X-SMTP-RCPT:"); however, this would require changes in mail programs in foreign environments and might risk disclosure of private information (see Section 7.2)."* |
| §7.2 | 4218-4223 | *"Especially when more than one RCPT command is present, and in order to avoid defeating some of the purpose of these mechanisms, SMTP clients and servers SHOULD NOT copy the full set of RCPT command arguments into the header section, either as part of trace header fields or as informational or private-extension header fields."* |

## Notes

RECOVERED BY THE RE-SWEEP. The capped sweep recorded it in EnvelopeFoldedIntoHeaderSection's notes as a candidate it had folded away ("PrivateInformationDisclosedByEnvelopeHeaders") — the cap is exactly why it had no slot. It earns its own card because the disclosure is a distinct, irreversible state change with a different subject (the recipients, not the message's routing) and because §7.2 supplies a normative rule the fold breaks. Strength: the §3.7.1 arm is a hypothetical ("might risk"); the §7.2 arm is a real SHOULD NOT at lines 4220-4223 — so the honest reading is that the fold §3.7.1 contemplates is the act §7.2 forbids. \<Green@foo.com> is real: it is the RFC's own recipient in the Appendix D.1 scenario, line 4897. Rejected alternative names: PrivateInformationDisclosedByEnvelopeHeaders (the capped sweep's), BlindCopyRecipientsExposed, RcptArgumentsCopiedIntoHeaderSection. Sibling in the trace chapter: the same SHOULD NOT also bans copying RCPT arguments into the FOR clause of a Received: line. Which project screen would have killed it: inbound-only scope; the consumer test / G1 would ask what reads a disclosure.

FIELD HYGIENE PASS: struck message_ref (example f2C8D14) — RFC 5321 supplies no message identifier; the disclosed recipient list is itself the fact and the identity of this event. The \<Green@foo.com> citation was re-checked against the source and holds: line 4897 reads C: RCPT TO:\<Green@foo.com>. The two surviving payload fields are the only ones with independent RFC sources in this record.
