## Notes

RECOVERED BY THE RE-SWEEP. RFC 5321 specifies no authentication mechanism, so this event is named by reference only — which is why it must be recorded rather than assumed, the whole of 7.1 turning on what such an event does and does not establish. Folded here: ResponsibilityHandedOffInTrustEnvironment (4180-4182), a real state change judged too thin at this cap and the direct ancestor of the project's responsibility-boundary question. Rejected names: PeerAuthenticated, ClientAuthenticated, TransportAuthenticationEstablished. Cross-referenced not merged: RecipientRejectedForPolicy (4.1.4 lines 2498-2500) — a denial is not an authentication. Screens that would have killed it: HELO-only charter, twelve-slice model. FIELD HYGIENE: struck relying_party and peer_address. The relying party is the other end of the same channel and the channel is the identity here; the peer address adds nothing once the party is named, and RFC 5321 supplies no session key to fabricate one from. authenticated_party survives because 4178-4180 is a constraint on it rather than on the event: what is authenticated is a SERVER, never a user or a user machine, so this field can never carry a user and any user field would be fabrication. Value is a walk-scene domain; the spec offers no instance of its own.
