# `MessageHandedOffToMailUserAgent`

A delivery SMTP system passed the message directly to a mail user agent rather than depositing it in a store, transferring responsibility out of the transport system.

## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §2.3.10 | 807-810 | *"A "delivery" SMTP system is one that receives mail from a transport service environment and passes it to a mail user agent or deposits it in a message store that a mail user agent is expected to subsequently access."* |
| §2.3.3 | 663-667 | *"the final ("delivery") MTA would be thought of as handing the mail off to an MUA (or at least transferring responsibility to it, e.g., by depositing the message in a "message store")"* |

## Notes

RECOVERED BY THE RE-SWEEP. §2.3.10 807-810 states two arms — pass to a mail user agent, or deposit in a message store — and every inherited candidate carried only the second; MessageDepositedInMessageStore (candidate 50) even names this one in its notes as 'a genuine sibling' it had no room for. The distinction is real and not cosmetic: in the deposit arm the MUA collects later and the store is a durable intermediary, in the handoff arm there is no intermediary and the responsibility moves in a single act. §2.3.3 664-666 says the same thing about the delivery MTA in the same two arms. Note the RFC's hedge at 665-666, 'or at least transferring responsibility to it' — the spec is not sure the handoff is of the message rather than merely of the duty, which is worth marking rather than deciding. ⚠️ §2.3.3 668-671 warns that 'the implied boundaries between MUAs and MTAs often do not accurately match common, and conforming, practices', so do not treat this event as a crisp system boundary. Screens: the responsibility-boundary cutoff and inbound-only scope; the altitude tiers put the MUA outside the Protocol tier entirely. ⚠️ FIELD HYGIENE PASS 2026-08-09 — two fields struck. message_id: RFC 5321 supplies no message identifier (§4.4's ID clause at line 3336 is optional and belongs to the receiver's Received: stamp; msg-id is RFC 5322's), and f2C8D14 is this project's minted queue_id value. Identity here is the recipient whose agent is being handed the message — and the RFC gives nothing else, which is consistent with its own admission at 4725-4726 (Appendix B) that 'the MTA-UA protocol is a private matter'. handed_off_at: struck as the event's own occurrence time.
