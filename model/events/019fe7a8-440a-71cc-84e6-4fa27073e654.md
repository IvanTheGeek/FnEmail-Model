## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §4.5.3.1.4 | 3500-3502 | *"The maximum total length of a command line including the command word and the \<CRLF> is 512 octets. SMTP extensions may be used to increase this limit."* |
| §4.5.3.1.9 | 3554-3555 | *"Errors due to exceeding these limits may be reported by using the reply codes. Some examples of reply codes are:"* |
| §4.5.3.1.9 | 3557 | *"500 Line too long."* |
| §4.3.2 | 3060-3061 | *"500 For the "command line too long" case or if the command name was not recognized."* |

## Notes

Inherited from candidate 329; citations re-checked and correct. The command_verb field carried by 329 is DROPPED here, and the drop is the finding: an over-length line is refused before it is parsed, so naming a verb claims knowledge the server does not have — a field that looked essential and was actually a fiction. 512 octets INCLUDING the command word and the \<CRLF> (3500-3501), and extensions may raise it (3501-3502), so limit_octets is a real per-server, per-session fact rather than a constant. §4.5.3.1.9 introduces its codes with "Some examples of reply codes are:" — they are EXAMPLES, NOT normative assignments, which is easy to lose; the reply_text is operator-configurable under ReplyTextCustomized. Rule 2 applies to the sample texts: the RFC's 500 example ends with a period, "500 Line too long.", and its 501 example does not, "501 Path too long" — copied as written in each event. Sibling folded here: the reply-line limit of §4.5.3.1.5 (3506-3508), the same 512 constraining the SERVER's output rather than the client's input. Note the shared code: 500 answers both this and UnknownCommandRejected, so the code alone cannot tell a client which fault it hit.

FIELD HYGIENE PASS (chapter 14): four fields struck. session_id struck — RFC 5321 names no session, transaction or connection identifier, and f2C8D14 is nowhere in the RFC; identity here is position in the session. reply_code and reply_text struck: 500 is fixed by the event's meaning, and "the text is for the human user" (2558-2559) — section 4.5.3.1.9's sample text is preserved in the note above under rule 2, which is where a quotation belongs, rather than carried as payload. limit_octets struck, which supersedes the inherited note's argument that it is a per-session fact: it may vary by session, but the configured ceiling is SizeLimitConfigured's fact, recorded once there and sourced to lines 3500-3502, and copying it onto every rejection is denormalization — the same call an earlier pass made when it dropped previous_text from ReplyTextCustomized. line_octets KEPT — it is measured from an object the server discards unparsed, so no other event can carry it, and it is the one fact that makes the rejection meaningful.
