## Notes

Carried from the inherited candidate, with the RFC's own worked failure from D.3 added — real host names xyz.com and foo.com, and it is the same scenario that instantiates SelfIdentifiedInMailExchangerList one step later, so the two events are demonstrably one story. Strength note worth keeping: the first MUST is on a capability ('MUST be able to try'), which has no event of its own — only the outcomes do; the second MUST, on multihomed ordering, is on behavior. Siblings all carried: CandidateAddressesExhausted, AlternateAddressLimitReached, NextHopChannelEstablished. Opposite arm of the ordering MUST: CandidateAddressesTriedOutOfOrder. Rejected alternative names: NextHopConnectionRefused (too narrow — failure_kind covers refusal, timeout and 4yz), CandidateAddressAttemptFailed. Which project screen would have killed it: the inbound-only scope. ⚠️ FIELD HYGIENE PASS: struck message_id (example \<f2C8D14@foo.com>). RFC 5321 supplies no message identifier — §4.4's ID clause is optional and is the receiving host's trace entry (3329, 3336-3337), §6.4 line 4131 shows a message may carry none, and f2C8D14 is this project's own minted value, absent from the RFC — and this event's stream root is the next-hop destination, not a queue entry, so no queue id belongs here either. Identity is the address attempted, at its position in the ordered candidate sequence. failure_kind survives as an observation and not a rendered decision: D.3 at 4997-4998 records the RFC's own instance of an attempt that 'fails' without naming a cause, so the value stays illustrative.
