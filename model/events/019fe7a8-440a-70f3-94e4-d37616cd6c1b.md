## Notes

Recovered by the re-sweep from the caching paragraph's justification clause, which every sweep read as commentary rather than as a described state change. Doubtful because the RFC states it as a possibility ("may be returned") rather than as behavior anything must or should exhibit, and because it is the extension-negotiation chapter's material reached from an odd door. Kept because it is the fact that makes NegativeResponseCached dangerous, and because it is a genuine server-side change: the advertised capability set is state, and it moved. Rejected name: DifferentExtensionSetReturnedForRepeatedEhlo. Screens: the HELO-only charter kills it outright, since the current model never issues EHLO at all. ⚠️ FIELD HYGIENE PASS: NOTHING STRUCK, and the record is worth reading for what it never had. Its stream root is Session, and RFC 5321 supplies no session identifier — a grep for session, transaction and connection identifiers over the whole text returns nothing — so no such key was available to fabricate here and none is added. While the session lives, the channel itself is its identity, and server_host names the far end of that channel. extension_keywords carries the RFC's own token: 8BITMIME appears at rfc5321.txt:922.
