# `MessageQueuedForDelivery`

A message that could not be transmitted immediately was written to the outbound queue together with its envelope, so it now has a lifetime independent of any session.

## Notes

MUST at 3690-3692, and a second independent MUST at §5.1 3840-3842 for the temporary-DNS-error path. Merged from three candidates naming one state change: MessageQueuedForDelivery, MessageQueuedForSubsequentDelivery and MessageQueuedAfterTemporaryDnsError — rejected names all recorded here, and the DNS variant is the same queue-entry creation with a different trigger, so the address-resolution chapter should cross-reference rather than re-declare it. The payload is dictated by the RFC itself (3692-3693), which is why the envelope paths sit on the event and not merely on the message; forward_paths is genuinely a List. Dropped as derived: attempt_number and any queue-depth count. Opposite event: UnsentMessageDiscardedWithoutQueuing. §3.6.3 1478-1481 is the negative definition — a client that cannot do this is the reason submission servers exist. Screens that would have killed it: inbound-only scope, responsibility-boundary cutoff, HELO-only charter; the twelve-slice model has no queue at all. ⚠️ FIELD HYGIENE PASS: RFC 5321 supplies no session, transaction or connection identifier — grep over the whole text finds none — so nothing of that kind may sit on this or any event in the chapter. queue_entry_id is kept because §4.4's trace grammar admits an optional ID clause, `ID = CFWS "ID" FWS ( Atom / msg-id )` at rfc5321.txt:3336, which is the one place the spec carries a queue identifier as data; the value f2C8D14 appears nowhere in RFC 5321 and is this project's own minted example, traceable to commit 6acfc68. STRUCK: destination_host, derived from forward_paths by address resolution and therefore a read model's fold — the RFC names only the message and the envelope as the entry's contents (3692-3693). queued_at is kept rather than struck as a bare occurrence time because two RFC rules measure from exactly this moment: the backoff policy keys on "the first hour the message is in the queue" (3720-3723) and the give-up time runs from it (3709-3710).
