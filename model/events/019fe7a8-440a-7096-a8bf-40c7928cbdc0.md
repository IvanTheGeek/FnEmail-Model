## Notes

Deprecated, not impossible, and kept for one specific reason: it is the only event in the entire specification in which a session's actors change identity mid-connection. Any model that assumes a fixed client and a fixed server for the life of a connection carries an unstated invariant, and this is the event that breaks it — worth knowing even if TURN is never implemented. SHOULD NOT, and conditional: permitted where the server can authenticate the client, which is what makes peer_authenticated the fact that decides rather than decoration. The failure arm is named in the spec itself — mail diverted from its correct destination. Precondition sibling not carried: PeerAuthenticated, the transport-level authentication §7.1 discusses, which only authenticates one server to another and not a user. Screens: the HELO-only charter, the inbound-only scope, and the twelve-slice model all kill it; Appendix F is outside every altitude tier the project has drawn. FIELD HYGIENE PASS: struck 3 fields. session_id struck: no such key in the spec — and this event is the one that shows why a session key would have been actively misleading, since the two ends swap roles while the channel stays the same. session_peer struck as the far end of that channel, recorded at TransmissionChannelOpened. ⚠️ peer_authenticated struck, against the note above: whether the peer was authenticated is a status folded from whether an authentication happened — the PeerAuthenticated sibling the note itself names — and §F.1 lines 5169-5171 states it as the condition under which TURN may be used, not as a fact this event observes. The point survives in prose: authentication is the condition, and its absence is what §F.1 says makes mail divertible. new_sender survives as the fact that changed.
