## Notes

Inherited from candidate 330; citations re-checked and correct. Rule 8 pays off here exactly as the rule predicts: 256 octets "including the punctuation and element separators", so for \<Smith@bar.com> the angle brackets are counted, and a placeholder like \<address> hides that completely — the brackets are path syntax, not notation. Two sub-limits ride underneath and can each be breached while the path total stays legal: local-part 64 octets and domain 255 octets. Their events, LocalPartLengthExceeded and DomainLengthExceeded, are named here rather than given rows for budget and are worth splitting out — they fail at different parse stages, they carry different reply texts, and a facilitator would ask. §4.5.3.1.2 covers "a domain name or number", so an address literal such as [192.0.2.10] is measured by the same rule. The reply text is quoted without a trailing period because the RFC writes it that way; see the note on OversizedCommandLineRejected.

FIELD HYGIENE PASS (chapter 14): four fields struck. session_id struck — RFC 5321 names no session, transaction or connection identifier, and f2C8D14 is nowhere in the RFC; identity here is the transaction plus the command's position. reply_code and reply_text struck as the decision rendered and as text "for the human user" (2558-2559); the RFC's own sample stays quoted in the note under rule 2. limit_octets struck as SizeLimitConfigured's fact, sourced to lines 3495-3496. path_octets KEPT — the path is refused, so no mailbox record carries it, and the measurement is what makes the rejection meaningful. command_verb KEPT because a reverse-path and a forward-path are different objects failing the same ceiling.
