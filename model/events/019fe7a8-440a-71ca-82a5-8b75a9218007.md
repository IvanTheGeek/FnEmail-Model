# `MailParametersRejected`

## Notes

Merged from candidate 239 and the parameter arm of 173; citations re-checked and correct. THE STRENGTH IS A RULE 3 TRAP, flagged in 173's notes and confirmed by opening the file: 2232 reads "it will return code 555" and 2237 reads "it should return code 455" — both lowercase, neither an RFC 2119 keyword. Do not upgrade them from memory; a reader who assumes MUST here will build a conformance test the spec does not support. 455 and 555 are the same complaint with two lifetimes, transient versus permanent, and they are kept in one event because the fault (the parameters, not the address) is identical while the reply code carries the lifetime — the opposite call from RecipientBufferLimitReached versus RecipientLimitEnforcedBySitePolicy, where the two limits have genuinely different causes. 555 is the only 5yz code whose text names specific commands, making it the narrowest code in the table. Rejected alternative names: ParameterRefused, EsmtpParameterUnsupported. Screens: the HELO-only charter kills it outright — no ESMTP parameters exist in a HELO session — and it is the cleanest example in the chapter of a charter decision hiding a whole family of events.

FIELD HYGIENE PASS (chapter 14): session_id struck — RFC 5321 names no session, transaction or connection identifier, and f2C8D14 is nowhere in the RFC; identity here is the transaction plus the command's position. reply_code struck, and the cost is real enough to record: section 4.1.1.11 lines 2230-2237 assign 555 to "does not recognize or cannot implement" and 455 to "temporarily unable", so the code is fully determined by which condition holds — it is derived from the condition, not an independent fact. This supersedes the inherited note's reasoning that the code carries the lifetime: the CONDITION carries the lifetime and the code renders it. The distinction should therefore be carried by the condition itself; a refusal_lifetime field with values permanent and temporary is NAMED here rather than added, because inventing a field is what this pass exists to undo, and the choice is a later step's. rejected_parameter and command_verb KEPT — section 4.1.1.11 scopes the fault to MAIL FROM and RCPT TO, which are different transaction steps.
