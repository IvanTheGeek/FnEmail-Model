## Data

**No data.** The method sanctions this: *"If an event has no meaningful payload beyond its identity (e.g., a simple state transition), it is fine to have no fields or just the identity key."* It also warns, of a different case, that *"An event without fields is an opaque label"* — both are recorded here rather than reconciled, because reconciling them is a later step's work, not Brain Storming's.

## Notes

Merge of two sweep candidates for one state change: MailDataTransferAuthorized (§4.1 span) and MessageTextCollectionBegan (§3.3 span). Rejected alternative names carried forward: MessageTextCollectionBegan, DataPhaseEntered (the project's existing name), ContentTransferAuthorized, MailDataTransferGranted. The mode switch IS the state change — identical octets mean different things before and after — which is why it is an event and not merely a reply. Strength is deliberately weak on both sides: §4.1.1.4 says "normally sends" with no 2119 keyword, §3.3 says "If accepted"; the RFC's own term for 354 is "Intermediate reply" — it neither accepts nor refuses. Reply text verified at 2844 (also §4.2.3 line 2882) and in the Appendix D examples; it is operator-configurable, so it is standard-font content in any rendering, not protocol-fixed. §4.3.2 line 3113 was added by re-sweep: it is the one place the whole DATA sequence is written as a sequence. Screens: the 'one event per command' target would fuse this with DataRequested and lose the mode switch; the consulted-view/decision lens would file the 354 as a reply rather than a fact.

FIELD HYGIENE PASS: struck all four fields. session_id and transaction_id are fabricated — RFC 5321 names no session, transaction or connection identifier; identity here is the channel itself plus position in the session, and the mode switch this event records is a property of that channel. reply_code is struck under the method's ban on computed and derived values: 354 is the rendering of the decision the event's own name states, and nothing in RFC 5321 carries the code as data beyond the wire. reply_text is struck for the same reason and a second one the note above already establishes — it is operator-configurable, so it is a rendering twice over. The event is now fieldless and that is the correct shape: what changed is the meaning of every subsequent octet, and there is no payload that carries it.
