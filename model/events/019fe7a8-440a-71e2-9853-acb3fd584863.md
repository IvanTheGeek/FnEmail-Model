## Notes

RECOVERED BY THE RE-SWEEP. The failure arm of 7.4, named outright in a single sentence and carried by no inherited candidate — the arm, not the honored path. A forged 251 permanently poisons the client's address book and the poisoning outlives the session: unlike almost everything else in SMTP, this state change is not undone by the connection closing. Natural hotspot: the spec offers NO way to be certain of the server's authenticity, naming a precondition it does not provide. Strength: 'may be subject to' — a consequence, not a rule. Rejected names: AddressBookPoisoned, RoutingRedirectedByForgedReply, ManInTheMiddleRedirectionAccepted. Deliberately NOT merged with AddressBookEntryUpdated: merging the honored and attacked arms would make the attack invisible, which is the whole content of 7.4. Screens that would have killed it: all of them. FIELD HYGIENE: struck reply_code (551), the rendering again. Corrected attacker_supplied_address, which read \<Smith@203.0.113.20>: an IPv4 address in a mailbox is an address-literal and must be bracketed — 4.1.3 line 2387 shows the form, [123.255.37.2] — so the old value was not a legal SMTP mailbox and would have taught a walk the wrong syntax; rule 8 cuts both ways, real data has to be really valid. apparent_server is the field the subsection turns on, 4286-4290 being entirely about whether that identity is genuine while RFC 5321 supplies no mechanism to check it. No identity key fabricated.
