## Notes

MERGE: absorbs PostmasterAddressProvisioned (rejected name; its citation was §3.1 969-971, which calls the address 'required' only in passing — the normative MUST is §4.5.1 3394-3396, and the inherited record correctly flagged that it had not opened §4.5.1). Strength MUST, with exactly one escape, carried as its own event (ConnectionRefusalConfigured). Case-insensitivity was an explicit field rather than an assumption because local-parts are otherwise case-sensitive in SMTP; the RFC's own casing is the evidence — 'postmaster' at 3395 and 3399, 'Postmaster' at 3401 and 3405 — and rule 2 keeps those as written. Likely rather than certain: the RFC states the obligation, never the provisioning act, so the event is inferred from a MUST. Siblings kept separate rather than merged: MailProblemContactPointPublished (a weaker optional fact the same sentence says does NOT discharge this obligation), DomainlessPostmasterSupportProvisioned (the RCPT TO:\<Postmaster> case), MailServiceDomainAdded (which fixes the extent of the obligation), PostmasterMailBlocked (its override). Opposite arm, never stated by the RFC: PostmasterMailboxDecommissioned. Screens: the altitude tiers put mailbox provisioning at Infrastructure, the consumer test G1 finds nothing reading it, and the one-event-per-command target has no command for it. FIELD HYGIENE: struck two fields. local_name is a constant — line 3395 fixes the reserved name, so the field could only ever hold postmaster, and the event name already carries it. case_insensitive is the MUST itself restated as a Boolean (3395-3396), true in every conforming instance; the reasoning above is preserved instead of the field, per the method's rule against padding. No session, transaction or connection key was present to strike; RFC 5321 supplies none, and identity here is the domain the mailbox was provisioned at.
