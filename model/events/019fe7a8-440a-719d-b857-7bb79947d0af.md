## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §4.1.5 | 2536-2541 | *"As specified in Section 2.2.2, commands starting in "X" may be used by bilateral agreement between the client (sending) and server (receiving) SMTP agents. An SMTP server that does not recognize such a command is expected to reply with "500 Command not recognized". An extended SMTP server MAY list the feature names associated with these private commands in the response to the EHLO command."* |
| §2.2.2 | 571-575 | *"In addition, any EHLO keyword value starting with an upper or lower case "X" refers to a local SMTP service extension used exclusively through bilateral agreement. Keywords beginning with "X" MUST NOT be used in a registered service extension."* |

## Notes

The most unusual actor in the whole spec: two human operators agreeing outside the protocol, whose agreement then changes what the protocol permits between exactly those two hosts. Stated plainly at 2536-2538 and never given a name. Likely rather than certain because the agreement is out of band by definition, so the RFC can only refer to it, never specify it. §8 4394-4395 added by the re-sweep — it is the registry-side mirror of the same rule and the reason this event belongs beside ServiceExtensionRegistered: the X prefix is exactly the boundary between what IANA governs and what two operators may settle privately. The listing question carries a genuine ambiguity worth a hotspot 🟥: under the MAY at 2540-2541 a private command may or may not appear in the EHLO keyword list, so the advertised set is not a complete statement of what a server accepts. XFORWARD is a real X-command in wide use. Screens: all of them, and the HELO-only charter twice over. Kept because the question of who else acts has an answer here — people, before any connection exists. FIELD HYGIENE: struck listed_in_ehlo. The MAY at 2540-2541 is addressed to 'An extended SMTP server', a different subject from the two operators whose agreement this event records, so the listing is a property of the server's advertisement configuration rather than a fact of the agreement; the hotspot it carried is preserved in these notes, where it loses nothing. The two host fields are the identity pair — the agreement binds exactly two systems and nothing else identifies it — and command_verb's example is labeled illustrative because RFC 5321 gives the X prefix without ever naming a command.
