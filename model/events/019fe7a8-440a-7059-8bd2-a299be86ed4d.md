# `FinalDeliveryMade`

A message left the SMTP environment — reaching the destination user or an associated mail drop — which is what obliges the delivering server to write a Return-Path.

## Notes

Inherited candidate 200, kept. The chapter's other spine event: the obligation created at ResponsibilityForMessageAccepted is discharged here. Carries a genuine RFC ambiguity that earns a 🟥 under rule 12 if it ever reaches the model — 3226-3228 concedes the server often cannot tell whether it is making final delivery, so the event's own trigger condition is not reliably decidable at the moment it must be decided, and the spec's answer is not to resolve it but to let downstream systems repair the result (3229-3231). Rejected alternative names: MessageLeftSmtpEnvironment (arguably better, because it is the RFC's own definition sentence and names the state change rather than the act), FinalDeliveryPerformed, MessageDeliveredOutOfSmtp. FinalDeliveryMade is kept because it matches the RFC's quoted term of art, 'final delivery'. The three destination_kind values the RFC itself offers are destination user, mail drop, and another mail system — the last of which is split off as MessageForwardedToAnotherMailSystem below, because it is not final at all.
