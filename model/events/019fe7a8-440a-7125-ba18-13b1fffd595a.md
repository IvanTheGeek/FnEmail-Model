## Notes

RECOVERED BY THE RE-SWEEP. The capped sweep named it in MessageGatewayedFromForeignMailSystem's notes as "its own event" and had no slot. It is the payoff event of the whole gatewaying chapter: the loop lands back on the mailing list address the message came from, and by then several hops and possibly two environments separate the effect from the cause. "almost inevitable" (line 4786) is unusually strong language for an appendix. Cross-reference, deliberately NOT merged: MailLoopDetected (§6.3 lines 4067-4072) in the loop-control chapter is the DETECTION — a different actor, at a different host, possibly never happening, and §6.3's own MUST covers only "trivial loops", which a two-environment loop is not. Kept separate on the brief's rule that a detection is not the thing detected. \<staff@foo.com> is real: it is the RFC's own list pseudo-mailbox in the §3.9 material. Rejected alternative names: MailLoopClosedThroughGateway, MessageReturnedToOriginatingEnvironment. Which project screen would have killed it: responsibility-boundary cutoff outright — the loop closes long after any transaction this server could see.
