## Notes

RECOVERED BY THE RE-SWEEP — the violated arm of the §4.5.1 MUST, which no inherited candidate carried. The spec names the resulting wire behavior itself at §3.5.3 3380-3381 ('not in full compliance'), so this is not speculation about a hypothetical bad server: RFC 5321 describes it. VRFY is the realistic example because §3.5.2 1359-1362 permits disabling it, which produces the very 500/502 §3.5.3 calls non-conforming — the same tangle recorded on VrfySupportDisabled, reached from the other side. Distinguish carefully: RequiredCommandLeftUnimplemented is the implementer never building it; VrfySupportDisabled is an operator switching off something that was built. Different actors, different streams, different cures — do not merge. The runtime arm, CommandRejectedAsUnimplemented, is another chapter's. FIELD HYGIENE: struck reply_given_instead (502). That code is the wire rendering the server emits when the missing command later arrives — §3.5.3's SHOULD governs the reply, not this shipping event — and it is derived from the omission, so by the method's own rule it belongs to the runtime arm and to read models over it. omitted_command survives and genuinely varies across the nine at 3384-3392, with VRFY sourced at line 3392.
