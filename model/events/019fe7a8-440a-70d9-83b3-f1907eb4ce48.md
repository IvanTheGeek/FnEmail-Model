## Notes

MUST, with both the code AND the text fixed by the RFC — one of the very few places where the reason text is specified rather than left to the operator, which matters for the monospace/standard-font convention in AGENTS rule 5. Line 1160 is the general rule this is an instance of, and it closes §3.3. stream_root is Session rather than Transaction precisely because there IS no transaction — that is the event's content, and it is the reason this cannot be folded into the transaction stream. Siblings the §3.1-3.3 sweep folded in here and that a later step should split: the same 503 for commands arriving between a 554 greeting and QUIT (a SHOULD, at 978-979), and a syntax rejection for the colon-spacing error the RFC calls 'a common source of errors' at 1093-1096 — for which §3.3 gives NO code and which is now carried by TransactionCommandArgumentRejected instead. Rejected alternative names: RcptWithoutMailRejected, BadSequenceReported.

FIELD HYGIENE PASS: struck three fields, leaving the event FIELDLESS. offending_verb (RCPT) goes as a constant restating the event's name — this event can only ever be about RCPT, and a field whose value is fixed by the name is padding; the umbrella event CommandRejectedAsOutOfSequence keeps command_verb, where the value genuinely varies. reply_code (503) and reason_text ('Bad sequence of commands') both struck as the wire rendering of a decision. ⚠️ The note above makes the strongest available case for keeping the text — 'one of the very few places where the reason text is specified rather than left to the operator' — and it is a fact about the REPLY, which the citation at 1087-1089 preserves in full, code and text together. That the protocol fixes both halves of a rendering does not turn the rendering into payload; it makes the rendering deterministic, which is what a read model over this event would produce. Fieldless is the right shape and the stream_root carries the content: rooted in Session because there IS no transaction, which is the whole event.
