## Notes

Inherited (candidate 21) with fields re-based on the RFC's own worked values from D.4 rather than invented ones — rule 8. Strength: MUST include the mailbox (1225), MAY include the full name (1224), MUST NOT answer 250 without actual verification (1373-1374). The 250 form is fixed at 1228-1229 to either 'User Name \<local-part@domain>' or 'local-part@domain'. Rejected alternative names carried from the merge: VrfyAnswered, UserNameVerified, MailboxVerified, AddressVerificationAnswered, VerificationSucceeded — all rejected because they name the command or the lookup, and the state change worth recording is that information crossed the boundary and cannot be recalled. Opposite events: VerificationDeniedWithoutChecking (always-550), VerificationRefusedAsUnimplemented (500/502), and the two 252 declines. Sibling at larger blast radius: MailingListMembershipDisclosedViaExpn. Which screen would have killed it: the consumer test (G1) — nothing in an inbound model consumes a disclosure — and the guest-viewed-calendar test if the read and its disclosure are treated as one thing; the capture/decision two-kinds lens has no slot for it either. Recorded ambiguity: D.4 line 5114 shows a 250 disclosing a real full name without saying whether the address was actually verified, which §7.3 lines 4247-4248 would call a violation if it was only syntax-checked — the RFC's own scenario does not settle it. FIELD HYGIENE PASS: nothing struck — this event never carried an invented identity key, and all four values source. No session_id was present, and none belonged: a grep over rfc5321.txt for a session, transaction or connection identifier returns nothing, so identity here is the query itself (the user name asked about) plus the channel the answer went back down. requesting_client is not a fabricated key — §4.4 lines 3325-3327 make TCP-derived information a fact the server holds ('Information derived by server from TCP connection'), and §4.1.4 lines 2498-2500 make the client's IP address a legitimate basis for an access decision on exactly these commands. The value 203.0.113.20 is the walk scene's, not the RFC's, and is labeled so.
