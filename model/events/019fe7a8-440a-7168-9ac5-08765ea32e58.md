## Notes

RECOVERED BY THE RE-SWEEP as the violated arm of the MUST NOT at 1356-1357; no inherited candidate carried it. Strength: MUST NOT, unconditional and unhedged — one of only two flat prohibitions in §3.5. The honored arm is an anti-event (the server simply returns a bare address) and is deliberately not modeled; the violated arm changes the requester's world, because a source route it now holds will be used and will route mail through hosts nobody chose. Real data taken from the RFC's own source-route example at Appendix F, '@ONE,@TWO:JOE@THREE' (line 4807), rather than invented. The third citation is kept because it is the constraint that makes the prohibition non-obvious: a program-delivery address MUST be reported by the mailbox name that reaches it (1354-1356), so the server is required to translate rather than to expose the mechanism — the same instinct, stated positively. Rejected alternative names: PathDisclosedByVerification, ExplicitRouteLeaked, SourceRoutedReplyIssued. A companion provisioning event, ProgramDeliveryMailboxNameAssigned, exists in the inherited set (candidate 16) and belongs to a directory-administration chapter, not here. Which screen would have killed it: the consumer test, the responsibility-boundary cutoff, and the twelve-slice model; marked doubtful because the losing arm of a MUST NOT is a weak event on its own. FIELD HYGIENE PASS: nothing struck. No reply code, no invented identity key, and the substantive value was already the RFC's own — re-verified in this pass at line 4807, where '@ONE,@TWO:JOE@THREE' appears in Appendix F. This is the chapter's model record for field hygiene, and it got that way before this pass, by rule 8 being applied at sweep time rather than retrofitted. Identity is the query and the channel; RFC 5321 supplies no session key.
