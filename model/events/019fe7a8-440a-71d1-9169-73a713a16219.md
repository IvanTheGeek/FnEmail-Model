## Notes

Inherited from candidate 285; citations re-checked and correct. MAY. Three sub-cases hide in one bullet — supplying a whole date is not the same fact as supplying a zone for a time that was already there — so the event carries supplied_part rather than splitting into three; split it if the repair audit trail is ever modeled. The historical cause is stated outright at 4108-4112: split-UA clients with no clock and no concept of time zones. The correctness caveat at 4137-4139 is the strongest argument for recording the addition as its own event rather than silently amending the message: the value the server supplies MAY BE WRONG, and only an event distinguishes "the client said this" from "we guessed this". Screens: the inbound-only scope.

FIELD HYGIENE PASS (chapter 14): no field struck; one example corrected. added_by's value changes from mail.foo.com, which appears nowhere in RFC 5321, to foo.com, which Appendix D names as a host at 4882 and its own trace line uses at 5064; the field itself rests on section 4.4's By-domain clause at line 3319. origination_date keeps the walk scene's value rather than borrowing Appendix D's date at line 5014, so the walked path stays self-consistent, and its source is labeled as the walk scene rather than as the RFC. supplied_part is sourced to line 4133, which names date, time and time zone as three separate things.
