# `CommandRejectedAsUnimplemented`

The server refused a command it recognizes but has not implemented, with 502 — or refused an implemented command because one of its parameters is not implemented, with 504.

|:--|:--|:--|
| §4.2.4 | 2933-2936 | *"Questions have been raised as to when reply code 502 (Command not implemented) SHOULD be returned in preference to other codes. 502 SHOULD be used when the command is actually recognized by the SMTP server, but not implemented."* |

## Notes

Inherited from candidate 238; citations checked and correct. §4.2.4 exists solely because "Questions have been raised as to when reply code 502 ... SHOULD be returned in preference to other codes" (2933-2934) and answers with two SHOULDs, not MUSTs — so the 500/502 split is advisory, which means a receiver's choice between them is a judgment and a reasonable hotspot. 504 is folded in as the parameter-level refinement; split it out if command parameters are modeled, since the state change differs (the command is implemented, only the parameter is not). EXPN is the real example rather than VRFY: EXPN is not in the §4.5.1 required subset, so 502 for it is legal, whereas 502 for VRFY is the violation recorded in RequiredCommandRejectedAsUnrecognized — the two events are distinguished by whether the verb is required, not by the code. §4.3.2 adds a deployment-era fact that dates the reply: 502 to EHLO is "permitted only with an old-style server". Rejected alternative name: CommandNotImplementedRefused.

FIELD HYGIENE PASS (chapter 14): session_id struck — RFC 5321 names no session, transaction or connection identifier, and f2C8D14 is nowhere in the RFC; identity here is position in the session. reply_code struck as the decision rendered; the cost is recorded rather than patched — with the code gone, the 502 arm and the 504 arm are distinguished only by whether unimplemented_parameter is present, and if that proves too thin the answer is to split the parameter case into its own event, as the inherited note already proposed, not to restore the code. unimplemented_parameter KEPT, and its example is corrected from SMTPUTF8, which appears nowhere in RFC 5321, to SIZE, which the RFC names at line 3524 and shows advertised at line 4890.
