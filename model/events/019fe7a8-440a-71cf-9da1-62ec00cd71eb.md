## Notes

RECOVERED BY THE RE-SWEEP. Candidate 326's notes named this as "the clearest both-arms pair in the span", said it was cut only for slot budget and that it should be restored — so the cap is documented as having taken it, and here it is back. It is the sharpest violation in the chapter because it is SILENT: the client was told 250 for those recipients and will never learn they were dropped, so no client-side event can ever record the loss, and the mail simply does not arrive. That silence is why it earns a row rather than a note — an event is the only place the fact can exist. Strength: MUST, on behaving "in an orderly fashion", with the discard named as the counter-example rather than as an explicit prohibition, which is a slightly indirect MUST worth flagging. discarded_forward_path is a List, one of very few genuine lists in this chapter. Rejected alternative names: RecipientsSilentlyDropped, AcceptedRecipientsAbandoned.

FIELD HYGIENE PASS (chapter 14): session_id struck — RFC 5321 names no session, transaction or connection identifier, and f2C8D14 is nowhere in the RFC; identity here is the transaction whose recipient list was cut. recipients_accepted struck as a derived fold over the transaction's accepted RCPTs. discarded_forward_path KEPT and it is the whole event: the client was told 250 for these paths and will never learn they were dropped, so if the list is not captured here the fact exists nowhere at all.
