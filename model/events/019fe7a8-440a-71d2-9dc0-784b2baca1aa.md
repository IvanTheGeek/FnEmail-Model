## Notes

Inherited from candidate 286; citations re-checked and correct. MAY. The header-side twin of FqdnInferredFromPartialName (raw candidate 256, route-resolution chapter): §5.1 forbids relays inferring FQDNs in the ENVELOPE and §6.4 line 4140-4141 forbids relays applying this correction to the MESSAGE — one prohibition stated in two sections about two different parts of the same mail, which is very easy to model twice by accident. Cross-referenced deliberately so a later reader does not merge them: the envelope and the header are different data, edited at different points, and only the header edit is this event. The real value Jones@foo is chosen because a bare host name with no dot is exactly the shape a split-UA client produced. Screens: the inbound-only scope.

FIELD HYGIENE PASS (chapter 14): no field struck; one example corrected. corrected_by's value changes from mail.foo.com to foo.com, sourced to Appendix D's trace line at 5064, with the field itself resting on section 4.4's By-domain clause at 3319. corrected_address is Appendix D's own value and original_address is that value with the domain truncated — illustrative, because the RFC shows no malformed example, but derived from a real one rather than invented whole.
