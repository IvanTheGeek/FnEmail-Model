## Notes

RECOVERED BY THE RE-SWEEP. The MUST NOT at 1505-1506 had only its honored arm (NotificationSuppressedToPreventLoop) in the inherited set. The violated arm is the whole reason the rule was written, and it is observable from outside in a way the suppression is not - the loop is visible in the trace headers, which is how such incidents surface. Strength: MUST NOT, unqualified. Downstream consequence: MessageLoopDetected fires at whichever relay counts the Received: fields. Rejected names: ErrorReportLoopStarted, NotificationAboutNotificationSent, BounceStormInitiated. Screens: all of them. --- FIELD HYGIENE: struck emitting_host (recorder's own domain; and the value mx.bar.com has no source anywhere in the RFC). The surviving address identifies the notification the loop is about, on the same reasoning as NotificationSuppressedToPreventLoop: the spec supplies no identifier for a notification message, so the address it was addressed to is the only available handle. No session or transaction key existed to strike; identity here is the notification message itself.
