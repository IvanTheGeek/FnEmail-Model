## Notes

MERGE of two inherited candidates that are one state change at opposite values: GreetingDisclosureConfigured (7.5) and SoftwareVersionAnnouncementDisabled (3.1). Names rejected: both, plus BannerDetailReduced, ServerVersionConcealed, GreetingDisclosureSet. The merge is on the state — how much this server reveals — not on the verb, the disabled case being version_disclosed false, the same reasoning the 3.6 sweep used folding RelayServiceRefused into RelayPolicyConfigured. What the merge must not lose: 3.1's MAY is DOUBLED, implementations MAY provide the switch and operators MAY then use it, so the event exists only on servers whose implementer built it, while 7.5's SHOULD runs the other way, a SHOULD to DISCLOSE. That contradiction is the content of 7.5 and is resolved nowhere. The RFC's contested reasoning is worth preserving in its own terms: hiding vulnerabilities is not securing them (4300-4303). Real wire data: D.1 line 4886; D.3 line 5057 reads S: 250 xyz.com is on the air. Screens that would have killed it: altitude tiers, consumer test, HELO-only charter. FIELD HYGIENE: struck reason (security concerns). 3.1 lines 967-969 give the motive in a subordinate clause, 'where it causes security concerns', as the RFC's reason for permitting the switch, not as data the server records; a motive field on a configuration act is commentary. greeting_text survives as configured data rather than rendering — the operator sets the text and it persists between sessions — and version_disclosed records a configured state, false being the case 967-969 permits. Identity: the server, RFC 5321 having no configuration key.
