## Notes

RECOVERED BY THE RE-SWEEP. The inherited set carried only the honored arm. This is the harm the MUST at 1692 exists to prevent, and the RFC states the harm in its own words at 1725-1727 — the originator "has no control over the contents of the list and will typically find error messages annoying". Two distinct causes produce it and the event does not distinguish them, deliberately: ListReturnPathLeftUnchanged (a list that broke the MUST) and AliasExpanded (an alias, where reaching the originator is correct). A facilitator may want to split it on that basis; recorded rather than pre-decided, and no cause field is added because that would be a derived value. Rejected alternative names: BounceReachedOriginalSender, ErrorMessageMisrouted, OriginatorNotifiedOfListDeliveryFailure. Screens: responsibility-boundary cutoff, inbound-only scope, consumer test G1. FIELD HYGIENE PASS: reply_code struck — 1 field, on the same test as its sibling ErrorMessageReturnedToListAdministrator. The code is the rendering of a decision on the wire, RFC 5321 does not carry it as data on the notification, and the 550 instantiated here is Appendix D.1's reply at line 4898, spoken in a session that closed long before this bounce landed. Worth noting that the earlier pass's own discipline points the same way: the note above refuses to add a cause field because it would be derived, and a reply code is derived in exactly the same manner — it is the shape a decision took at the moment it was spoken, not a fact about where the bounce arrived. No identifier struck or added, for the reason recorded on the sibling: the bounce is a different message and the spec supplies nothing that links it to the original.
