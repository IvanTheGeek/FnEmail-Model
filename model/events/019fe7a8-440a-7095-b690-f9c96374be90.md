## Notes

The interesting property is negative: this is the one refusal in §3.8 where nothing closes, so its value to the model is that it fixes the boundary of the close arms by saying what does NOT terminate a session. 'expected to be tolerant' is not RFC 2119 keyword language at all — plain prose, stated immediately after a sentence calling the opposite 'in violation of this specification' — so the effective strength exceeds the wording, which is a trap for any sweep that greps for keywords. §4.3.2 adds a second violated arm this event does not carry: returning 500 to one of the REQUIRED commands is itself a violation, a different fact from closing on an unknown one. A run of these is exactly the shape §7.8 describes, which is how this event feeds ConnectionClosedDefensively.
