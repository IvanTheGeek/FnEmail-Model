## Notes

RECOVERED BY THE RE-SWEEP. The inherited candidate MailSessionRefusedAtGreeting named this sibling 'InterveningCommandRefused' in its notes and folded it away rather than raising it, so the 32-event cap plus the fold lost it entirely. It repeats: every command arriving between the 554 and the QUIT earns its own 503, so it is a distinct recurring event, not a one-shot. Kept apart from UnknownCommandRejected (500, an unrecognized verb) and from MailSessionRefusedAtConnectionOpening (the refusal itself) — this is a well-formed, understood command refused only because the session is already refused. SHOULD strength, sitting inside a MUST on waiting. Screens: the twelve-slice model has no post-refusal wait state at all, and the consumer test would ask what reads a 503. FIELD HYGIENE PASS: struck 2 fields. session_id struck — the spec names no session key; what identifies this event is its position in the session, between the 554 and the QUIT, which is precisely what the event name states and what no identifier could add. reply_code 503 struck as the rendering of the refusal; the '503 bad sequence of commands' wording stays where it belongs, in the quoted §3.1 line. command_verb survives as the one fact that varies — which command was refused.
