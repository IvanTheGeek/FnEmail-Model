## Notes

MERGE: RelayPolicyConfigured (§3.6.1) and RelayingPolicyConfigured (§3.3) are one state change described in two places; kept the shorter name, unioned the fields and the refs. Also absorbs RelayServiceRefused, considered and dropped by its own sweep on the correct ground that 'decline to act as mail relays at all' is this event with relayed_for_domains empty — a different value, not a different fact. MAY on every arm; nothing forces a server either way, which is exactly why the stance has to be a recorded decision rather than an implicit default. The RFC records the cost in the next breath (1084-1087) and then lays a MUST NOT on the CLIENT at 1085-1087 — restricted-capability clients must not assume any server will relay for them. Distinguish from RelaySourceAuthorized (§7.9, by source rather than by destination domain) and RelayDomainAuthorized (§3.5.3, the set consulted during address verification): three different sets, three different sections, cross-referenced and not merged. Runtime arm in another chapter: RelayingDeclined / RelayTaskDeclined. Screens: the altitude tiers and the HELO-only charter, which has no place for standing configuration at all. FIELD HYGIENE: struck relaying_permitted. It is derived — the record's own note above already argues that declining to relay at all is this event with relayed_for_domains empty, so the Boolean is that list's emptiness computed twice, and the method sends computed values to read models. source_routed_addresses_accepted survives because §3.6.1 1428-1430 makes it a genuinely separate MAY, on a different object from the destination set.
