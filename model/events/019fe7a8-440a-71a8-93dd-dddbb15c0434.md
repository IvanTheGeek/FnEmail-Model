## Notes

Carried from #68. The queue is named in this chapter only as a capability that weak clients LACK (1480), but it is what makes the word 'later' at 1495 possible: a server cannot 'later' find the destination incorrect unless the message survived the session. So the queue is implied twice in the same section from opposite directions, and neither mention specifies it. Strength: none stated for the queueing act. Siblings this chapter makes possible but does not name: DeliveryRetryScheduled, QueueLifetimeExpired, MessageDequeued - and DeliveryGivenUp, from 4.5.4.1. Rejected names: MessageEnqueued, DeliveryDeferred. Screens: responsibility-boundary cutoff, inbound-only scope, and arguably the condemned status register. --- FIELD HYGIENE: struck queued_at (event time restated). queue_id kept: this is the event that creates the queue entry, and 4.4's optional ID clause (3329, 3336) is what makes an id real data. The envelope stays because a queue entry that cannot reproduce it cannot make the 'subsequent delivery attempts' of 1480 - identity key plus the two facts the retry needs, and no more.
