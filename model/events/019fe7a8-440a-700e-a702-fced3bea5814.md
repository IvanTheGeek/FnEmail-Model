## Notes

RECOVERED BY THE RE-SWEEP — named as an uncarried sibling in the inherited MailExchangerAddressResolved notes under the rejected name MailExchangerTargetRejected, and given no slot. Strength: MUST on the DNS data (3855-3858), with the violation explicitly left unhandled — 'lies outside the scope of this Standard'. That is the sharpest 🟥 in the chapter: two conforming clients may do opposite things with the same broken zone, one treating the target as unusable and one following the CNAME anyway. Deliberately three defects in one event with a defect field, not three events, because the RFC groups them as 'any other response'; if a later step finds the handling differs by defect, it splits. Feeds NoUsableMailExchangerFound only if the client chooses to call it unusable — which the spec does not say. Do NOT merge with TargetNameResolvedToCanonicalName: a CNAME at the *queried name* is a legal chase, a CNAME at the *MX target* is a defect. Which project screen would have killed it: the four altitude tiers. ⚠️ FIELD HYGIENE PASS: nothing struck; no fabricated identity key was present. defect is not a computed value — it is the observed shape of the response, and the RFC's own enumeration at 3859-3860 supplies the example wording, so it is sourced rather than invented. exchanger_target is illustrative for the same reason as on MailExchangerAddressResolved: the RFC records no broken zone.
