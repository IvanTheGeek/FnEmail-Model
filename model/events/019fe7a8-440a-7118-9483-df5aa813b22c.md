## Data

**No data.** The method sanctions this: *"If an event has no meaningful payload beyond its identity (e.g., a simple state transition), it is fine to have no fields or just the identity key."* It also warns, of a different case, that *"An event without fields is an opaque label"* — both are recorded here rather than reconciled, because reconciling them is a later step's work, not Brain Storming's.

## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §3.7.2 | 1591-1592 | *"The gateway SHOULD indicate the environment and protocol in the "via" clauses of Received header field(s) that it supplies."* |

It has two fields only because they are genuinely the identity of the crossing, not padding. The consequence the RFC itself supplies is real (lines 1583-1585: the trace exists for debugging, and this omission removes the one clause that says which environment the message came from), which is why it is kept rather than set aside. A facilitator may reasonably fold this into ViaClauseRecorded as an absent field; recorded here so the decision is made rather than inherited. Opposite event: ViaClauseRecorded.
