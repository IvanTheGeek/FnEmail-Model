## Notes

RECOVERED BY THE RE-SWEEP as the violated arm of the SHOULD at 2199. The honored arm — the parameter being ignored — is an anti-event and is deliberately not modeled; the violated arm is a real state change, because whatever the server did with the string it was not nothing. Strength: SHOULD ignore (2199). The grammar at 2203 admits the parameter, so a server that acts on it is reading a value the protocol carries and the protocol says to discard: the private-use channel that §4.1.5 lines 2536-2541 licenses for X-commands, arriving through a command that is not supposed to have one. Marked doubtful: the RFC gives no example of a server doing this and names no consequence, so the event is inferred entirely from the existence of the prohibition. Rejected alternative names: NoopParameterIgnored (the honored arm, an anti-event), NoopArgumentProcessed, NoopUsedAsSideChannel (rejected as interpretation, not fact). Which screen would have killed it: every one of them — the consumer test, the capture/decision lens, 'one event per command', the twelve-slice model. Kept because the instruction is explicit that the violated arm of a SHOULD is where truncated sweeps lose events, and this is the smallest clear example of that in the chapter. FIELD HYGIENE PASS: struck session_id (f2C8D14), and CORRECTED the surviving value, which had the same fabricated key embedded inside it — parameter_string read 'keepalive f2C8D14'. That is the subtler half of the defect: a minted identifier smuggled into a free-text example, where a grep for the field name would never find it. RFC 5321 supplies no session, transaction or connection identifier, and f2C8D14 appears nowhere in the RFC; identity here is the channel and the command's position in the sequence. The parameter itself is real — the grammar at line 2203 admits it — but the RFC gives no example of one, so the value is now plainly labeled invented. No reply code was present. Already doubtful and left so; the sourcing reinforces the reason rather than changing it, since the event's one substantive field is a string the spec both admits in its grammar and tells servers to discard.
