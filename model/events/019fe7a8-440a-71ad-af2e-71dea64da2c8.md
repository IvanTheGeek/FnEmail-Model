## Notes

Carried from #81. A violation event, and doubtful for exactly that reason: the RFC forbids the act, so a conforming system never emits it. Kept because both arms are wanted and because a violation that a DOWNSTREAM system detects is a real state change for the detector, which is how corrupted-trace incidents actually surface. If it is dropped later, drop it for being unobservable from inside one system, not for being forbidden. The example value was changed by the re-sweep from 'Received:' to 'Subject:' - modifying a Received: line is separately and more strictly forbidden by 3178-3179, so using it as the example conflated two prohibitions. Strength: MUST NOT, restated for emphasis at 1528-1529 with a pointer to 7.9 (heading 4355, verified). Rejected names: MessageAlteredInTransit, RelayTamperedWithContent. Contrast the gateway's licence at 3.7.1 lines 1549-1552. --- FIELD HYGIENE: struck relay_host and observed_at. The Subject: example turns out to be sourceable after all - it appears in the RFC's own example message at 5016 (and again at 5068) - so its example_source is an RFC line rather than an invention, and the re-sweep's swap is vindicated by the file.
