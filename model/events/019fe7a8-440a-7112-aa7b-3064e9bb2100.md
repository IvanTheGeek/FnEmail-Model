## Notes

The surprising ruling: a box with SMTP on both sides is still a gateway, not a relay, if it rewrites addresses — classification follows behavior, not protocol. An address rewrite therefore silently upgrades a host's role and with it what the host is permitted to do to the message. Strength: LOWERCASE "should" at line 823, NOT the RFC 2119 keyword — the sentence is a definitional instruction to the reader ("For the purposes of this specification"), so do not promote it to SHOULD. This is one of three lowercase near-misses this chapter carries; the others are §3.7.5 line 1637 and Appendix E line 5138. Real data is what makes it visible: \<Smith@bar.com> becoming \<Smith@foo.com>; a placeholder shows nothing. Tension worth a hotspot: if the rewrite touches the local-part, §2.3.11 lines 847-849 is a MUST that only bar.com may assign semantics to Smith. Cross-reference, deliberately not merged: LocalPartRewrittenByIntermediateHost (ceded to the addressing chapter) is the general-intermediate-host case, this one is the firewall-as-gateway case. Rejected alternative names: FirewallRewroteAddress, EnvelopeAddressSubstituted. Which project screen would have killed it: inbound-only scope.
