## Data

**No data.** The method sanctions this: *"If an event has no meaningful payload beyond its identity (e.g., a simple state transition), it is fine to have no fields or just the identity key."* It also warns, of a different case, that *"An event without fields is an opaque label"* — both are recorded here rather than reconciled, because reconciling them is a later step's work, not Brain Storming's.

## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §3.3 | 1109-1114 | *"Since the mail data is sent on the transmission channel, the end of mail data must be indicated so that the command and reply dialog can be resumed. SMTP indicates the end of the mail data by sending a line containing only a "." (period or full stop). A transparency procedure is used to prevent this from interfering with the user's text (see Section 4.5.2)."* |
| §4.1.1.4 | 2003-2008 | *"The mail data are terminated by a line containing only a period, that is, the character sequence "\<CRLF>.\<CRLF>", where the first \<CRLF> is actually the terminator of the previous line (see Section 4.5.2). This is the end of mail data indication. The first \<CRLF> of this terminating sequence is also the \<CRLF> that ends the final line of the data (message text)"* |

Line numbers are into [`docs/rfc/rfc5321.txt`](../../docs/rfc/rfc5321.txt), the archived copy. Quotations keep the specification's own words and spellings (AGENTS.md rule 2).

## Notes

Merge of two identically-named sweep candidates (§3.3 span and §4.1 span); rfc_refs unioned, fields unioned. Rule 2 detail preserved from the §4.1 sweep: the RFC writes "The mail data are terminated" — plural verb — and the quote keeps it. The fact most easily lost, and the reason the §4.1.1.4 quote is carried in full: the first \<CRLF> of the terminating sequence is the one that already ended the last data line, so the terminator is not five extra octets on the wire. Strength: descriptive, not 2119 — but the surrounding MUST NOTs (ExtraLineEndingAppended, BareLineFeedTerminationAccepted) all attach to this act. Rejected alternative name: FinalPeriodSent. Deliberately kept apart from three neighbors that the RFC itself distinguishes: EndOfMailIndicatorRecognized (the receiver's side of the same octets), MailTransactionConfirmed (the same act's second meaning), and MessageContentStored (what the server does next). Screens: none kills it, but the responsibility-boundary cutoff ends the model at the reply this event provokes.

FIELD HYGIENE PASS: struck all three fields. transaction_id is fabricated — RFC 5321 names no transaction identifier; identity is the channel, and this event is fixed by position, since a transaction has exactly one end-of-data indication. terminator is struck as a constant: \<CRLF>.\<CRLF> is the same on every instance, so the field restates the event's meaning and carries no information about the occurrence — the RFC's own subtlety about the first \<CRLF> belongs in the note, where it already is, not in a payload. indicated_at is struck as the event's own occurrence time, which every event carries by construction. Fieldless is the right shape: the act is the fact.
