## Where RFC 5321 says so

| Section | Lines | Text |
|:--|:--|:--|
| §4.5.4.2 | 3776-3781 | *"The SMTP server SHOULD attempt to keep a pending listen on the SMTP port (specified by IANA as port 25) at all times. This requires the support of multiple incoming TCP connections for SMTP. Some limit MAY be imposed, but servers that cannot handle more than one SMTP transaction at a time are not in conformance with the intent of this specification."* |
| §3.8 | 1651-1653 | *"After detecting the need to shut down the SMTP service and returning a 421 response code."* |

## Notes

MERGE: absorbs SmtpServiceStarted (rejected name; same state change, one sweep reaching it from §3.8's shutdown clause and the other from §4.5.4.2's listen requirement — unioned here, which is why both citations stand). The purest 'precondition nobody wrote down': you cannot shut down a service that never started, so line 1651 presupposes this. SHOULD keep the listen pending 'at all times' (3776-3777), which makes ListenerStopped a conformance-relevant state change and not lifecycle noise. Concurrency limit is MAY, but 3779-3781 calls a one-transaction-at-a-time server not in conformance with the intent — a rare judgment on a configured VALUE rather than on a behavior, and the violated arm of a MAY. Sibling dropped for slot budget: IncomingConnectionRefusedAtCapacity, the runtime event when max_concurrent_connections is reached. Screens: the altitude tiers would rule bind_address and port Infrastructure by G4 and delete them; server_domain survives, since it is what the 220, 221 and 421 lines all carry. FIELD HYGIENE: struck three fields, and NOT on the screen named just above — these go on source and constancy, which is what this pass is allowed to apply. port (25) is a constant fixed at rfc5321.txt:3777, 'specified by IANA as port 25', so the field could hold only one value within RFC 5321. bind_address (192.0.2.10) has no source at all: nothing in RFC 5321 speaks of binding a listener to an address, so walk-scene data had been grafted onto a fact the spec never supplies. started_at is the event's own occurrence time, metadata rather than payload. max_concurrent_connections survives as a real MAY at 3779, with its value labeled illustrative because the RFC gives no number. No session, transaction or connection key was present; identity is the server's domain, which is what the 220, 221 and 421 lines carry, and the connections this listener accepts are exactly the objects RFC 5321 gives no identifier to.
