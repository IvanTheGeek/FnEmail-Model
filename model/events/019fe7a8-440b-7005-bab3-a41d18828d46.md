## Notes

MERGE of two inherited candidates naming one state change: HostileTrafficDetected (7.8) and AbusePatternDetected (3.8, reached through the parenthetical at line 1647). Names rejected: AbusePatternDetected, AttackDetected, PeerJudgedHostile, AbuseThresholdCrossed. Strength: 7.8 contains NO RFC 2119 keyword at all — 'rational operational behavior requires' (4347) is prose and 'it would be reasonable' (4351) is permission by rationale. The spec grants a permission then refuses to specify it ('the means of doing so are beyond the scope of this Standard', 4346-4347): a natural hotspot and the honest place to record that the threshold is undetermined. 3.8's MUST NOT is scoped by 'under normal operational circumstances', making this a FOURTH close arm beside the three bulleted ones, for which the current SessionClosed{cause} enum has no value. Same attack shape as AddressesHarvestedFromMailingList reached through RCPT instead of EXPN (7.3 lines 4275-4277). Screens that would have killed it: the condemned status register, the consumer test. FIELD HYGIENE: struck session_id (SessionId, f2C8D14). RFC 5321 names no session, transaction or connection identifier — the grep returns nothing — and while the session lives the channel is its identity; the one peer identity the spec acknowledges is the address the server derives from the TCP connection (4.4 lines 3325-3327, 'Information derived by server from TCP connection / not client EHLO'), which is why peer_address stays and now does the work session_id pretended to do. Its value was this project's own minted queue_id (commit 6acfc68) wearing a session key's name. Struck rejected_recipients too, closing the argument the merge left open: a list of recipients already rejected in this session is a fold over earlier events, a read model by the method's own rule, exactly as the rejected_recipient_count it replaced was. 7.8's criterion at 4349-4351 is a threshold over that fold, so the detection consumes a read model and does not carry it. The surviving pattern field is the RFC's own words; the earlier caution against inventing an enum of attack types stands.
