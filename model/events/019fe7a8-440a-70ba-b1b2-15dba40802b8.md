## Notes

CITATION FIX: the inherited candidate cited §3.3 lines 1017-1020 for a sentence that ends on 1018, and 1031-1034 for a quote that ends on 1033. Corrected here after opening the file (rule 3). Rejected alternative names: SenderIdentified, MailFromIssued, OriginatorDeclared. FnEmail already carries ReversePathDeclared under that exact name. The stated PURPOSE of the reverse-path is error reporting (1032-1033), which is what ties this event to any later non-delivery notification. mail_parameters is a List and is only legitimate when extensions were negotiated — the project's HELO-only charter would delete that field, and that screen is named, not applied. Rendering caution for whoever draws this (AGENTS rule 5): \<Smith@bar.com> outside a code span loses its angle brackets, and in SMTP the brackets are path syntax.

FIELD HYGIENE PASS: struck one field, declared_at. RFC 5321 puts a date-time only in the Received stamp's grammar at §4.4 3311-3313, so a declaration time on MAIL is ambient occurrence metadata, not payload; the example value was also not the RFC's own (5014 reads 'Thu, 21 May 1998 05:33:29 -0700'). reverse_path stays and is the event: \<Smith@bar.com> is the walk scene's sender and is also RFC 5321's own Appendix D value at 4893, so it is real data in both senses rule 8 cares about. mail_parameters stays because the grammar at 1027 provides for it, but its example is now labeled honestly — SIZE=1024000 is not sourceable in this document, and that fact is itself the check on whether the field belongs once the extension question is settled. No identity key was present to strike beyond what MailTransactionStarted already records; identity on this event is the forward-facing one, the reverse-path itself, plus position in the session.
