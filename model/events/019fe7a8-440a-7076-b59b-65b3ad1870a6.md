## Notes

A doubled MAY: implementations MAY build the switch, and operators MAY then use it, so the event exists only on servers whose implementer chose to build it. DELIBERATELY NOT MERGED with the inherited candidate GreetingDisclosureConfigured, even though both govern what the greeting reveals: §7.5 pushes the opposite way, a SHOULD to disclose, on the reasoning that concealing vulnerabilities is not securing them (lines 4299-4303). Merging a MAY-to-hide with a SHOULD-to-reveal would erase a real tension in the spec, and the brief forbids merging a refusal into an acceptance. Rejected alternative names: GreetingDisclosureConfigured, VersionDisclosureSuppressed, SoftwareIdentificationWithheld. Opposite event not carried, cut for the cap: SoftwareVersionAnnouncementEnabled. This is the 'what happens over time, not in a session' question answered directly — it decides the content of every later ServiceGreetingSent. Screens: every FnEmail screen kills it (no session, no command, no drawn consumer), yet the model already carries ServiceConfigured, and this is simply a second configuration fact on the same stream. FIELD HYGIENE PASS: struck 2 fields. disabled_at struck as the event's own occurrence time. reason struck — §3.1 lines 967-969 supplies exactly one motive, 'where it causes security concerns', so the field restated the RFC's own single named cause rather than recording anything that varies; the tension with §7.5's SHOULD to disclose is preserved in the prose above, where it belongs. What remains is server_domain, which is the identity of the configured server; RFC 5321 supplies no configuration or instance key of any kind.
