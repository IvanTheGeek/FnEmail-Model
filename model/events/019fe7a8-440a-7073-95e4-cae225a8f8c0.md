# `MailSessionRefusedAtConnectionOpening`

The server formally refused the mail session in place of a greeting, while deliberately leaving the connection open.

## Notes

Merged MailSessionRefusedAtGreeting (§3.1 sweep) and ServiceRefusedAtConnection (§4.2/4.3 sweep) — one state change, two names. Rejected alternative names: MailSessionRefusedAtGreeting, ServiceRefusedAtConnection, ConnectionRefused, TransactionFailed. It cannot be named TransactionFailed even though 554 is the transaction-failure code, because at connection opening there is no transaction to fail; the reply text is the only disambiguator, and 554 is NOT among the codes whose text a client may act on — §4.2 lines 2610-2612 name only 251, 551, 220, 221 and 421. That is a live RFC ambiguity, carried forward rather than resolved. Strengths inside one paragraph: MAY for the refusal, MUST for then waiting for QUIT, SHOULD for the 503 to intervening commands, SHOULD for debugging detail in the text. This is emphatically not a close — the connection stays open, which is what separates it from ConnectionClosedDefensively. Screens: the HELO-only charter and the responsibility-boundary cutoff both start after the greeting, so a connection that never greeted falls outside every current slice; the condemned status/phase register would also kill it, since the session is now in a 'refused but open' state. FIELD HYGIENE PASS: struck 3 fields. session_id struck — no such key exists in the spec; the open channel is the identity, and it was recorded at TransmissionChannelOpened. client_address struck for the same reason: the peer is the channel's, already recorded at the open, and repeating it here is duplication rather than a new fact. reply_code 554 struck as the rendering of a refusal the event name already states. refusal_text survives on the RFC's own terms — §3.1 lines 979-983 makes the text load-bearing by SHOULD, which is exactly the case where reply text is data and not decoration. Note the tension the strike sharpens: the same §4.2 carve-out that keeps 220/221/421 text machine-actionable pointedly excludes 554.
