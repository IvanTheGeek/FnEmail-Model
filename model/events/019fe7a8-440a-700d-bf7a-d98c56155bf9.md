## Notes

Carried from the inherited candidate at its original doubtful confidence; the §5.2 ref is retargeted from lines 3950-3951 (the IPv6-only skip, which now has its own event) to 3941-3943, where §5.2 actually speaks about what MX targets contain. Doubtful because it is the success arm of a lookup and reads like a query result — half of it belongs in the guest-viewed-calendar pile, and the inherited set-aside pile names it as the first candidate to fall if a later step wants a stricter line. Kept because the resolved address is the fact every delivery attempt is made against, and caching makes it outlive the query. Note the MUST binds the DNS *data*, not client behavior — an unusual shape. Opposite event, now carried: MailExchangerTargetFoundUnresolvable. Rejected alternative names: ExchangerAddressLookedUp (that is the read), NextHopAddressDetermined (collides with the candidate-list events). Which project screen would have killed it: the consumer test (G1) and the altitude tiers. ⚠️ FIELD HYGIENE PASS: struck record_type as a derived value — the address family is readable off the address itself (192.0.2.10 is IPv4, therefore an A RR), so carrying 'A' alongside it records nothing the addresses field does not already fix. §5.2 at 3941-3943 is what makes the pair meaningful, not a separate type tag. No fabricated identity key was present. exchanger is labeled illustrative: RFC 5321's only exchanger host names are D.3's xyz.com and foo.com, which are the delivery domains in that scenario rather than distinct exchanger hosts.
