## Notes

RECOVERED BY THE RE-SWEEP as the violated arm of the MUST at 3165-3166. Doubtful, and honestly so: the Stamp production at 3311 makes From-domain non-optional, so this is not merely a SHOULD ignored but ungrammatical output — a message carrying it is malformed, and §3.7.2 lines 1586-1588 then forbid the next receiver from rejecting it on that basis. That collision is the reason to keep the event: the spec mandates a shape, forbids enforcing it, and says nothing about what a reader should do with the wreckage. Worth a 🟥 under rule 12 if it ever reaches the model. Siblings: FromClauseComposed, TraceSourceNameStampedWithoutConnectionAddress, MailAcceptedDespiteMalformedTraceHeader (which is what the *next* hop does about it). FnEmail screens: essentially all of them — nothing in the current model has a seat for a counterparty's malformed output. ⚠️ FIELD HYGIENE PASS: struck the fabricated `message_ref` identity key — RFC 5321 supplies none, and f2C8D14 is this project's minted queue id rather than anything the RFC carries. What is left is the BY-domain, which is the only clause the malformed line still has: with From-domain missing, the stamping host is literally all the line identifies itself by, and that is a finding rather than a gap. Confidence stays doubtful for the reason already recorded, not because of this strike.
