## Notes

RECOVERED BY THE RE-SWEEP. The MUST at 1508-1509 had only its honored arm in the inherited set. This is the arm that produces bounce storms in the field: a notification with a routable reverse-path can itself be bounced, and the loop the null path exists to prevent is back on. Strength: MUST, scoped narrowly to notification messages. Ambiguity worth carrying: 'such a message' at 1508 refers back to 'a notification message' at 1507-1508, so the MUST binds only messages that ARE notifications - a server that mislabels a message escapes the rule by construction, and nothing defines what makes a message a notification. Rejected names: NotificationReversePathLeft, LoopPreventionOmitted. Pairs with NotificationLoopGenerated as cause and effect. --- FIELD HYGIENE: struck notifying_host (recorder's own domain). reverse_path_used survives as the one fact that makes the violation recordable - the routable path that should have been null - and its example is now labeled illustrative with both halves sourced, rather than left as the unexplained \<postmaster@bar.com> the sweep minted.
