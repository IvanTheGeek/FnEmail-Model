## Notes

RECOVERED BY THE RE-SWEEP — the violated arm of a MUST NOT stated twice, at §3.5.3 1373-1376 and §7.3 4241-4248, and absent from all 352 inherited candidates. This is exactly the loss the schema cap produced: every sweep kept the honored arm (MailboxExistenceDisclosedViaVrfy) and dropped the arm the RFC spends two sections prohibiting. Strength: MUST NOT, doubled. Why it is an event and not merely a non-compliance: the requester now holds a mailbox address it believes is real, and will act on it — the false belief is the state change, and it is durable in a way the reply is not. Rejected alternative names: SyntaxOnlyVerificationReturned, UnverifiedAddressConfirmed, FalsePositiveVerificationIssued. Sibling and opposite: MailboxExistenceDisclosedViaVrfy is the same 250 when the verification actually happened — the two are indistinguishable on the wire, which is the whole problem §7.3 is written to name, and a later step must not merge them on that ground. Also opposite: VerificationDeniedWithoutChecking, the other named non-conformance. Which screen would have killed it: the HELO-only charter, the consumer test (G1), and the 'only facts' rule if 'was it actually verified' is read as unobservable — but the RFC treats it as a fact about the server, not a derivation. Live illustration, left unresolved: D.4 line 5114 answers 250 with a full name and never says whether the address was verified. FIELD HYGIENE PASS: struck two fields. reply_code (250) went as a wire rendering. checks_performed ('syntax only') went as padding: the event's own name and meaning already say the server checked nothing but the syntax, so a field repeating it adds no fact, and §7.3 lines 4247-4248 that establish it are in the rfc_refs. echoed_address is kept because it is what the requester walks away holding — §7.3 line 4247 names it exactly, 'the address listed in the VRFY command' — but its value is now flagged as constructed rather than quoted: the RFC gives no worked example of this violation, so \<Crispin@foo.com> is assembled from the D.4 argument at 5113 and the D.1 host at 4886. Labeling it is the honest alternative to letting a plausible address pass as sourced. No invented identity key was present.
