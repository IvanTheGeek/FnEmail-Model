## Notes

Inherited candidate 337, kept, and deliberately NOT merged with DuplicateMessageReceived: one is a receiver fact at the wire, the other an irreversible mailbox fact, and the retry schedule can put days between them. The inherited copies_delivered: 2 field is dropped as a computed value under the only-facts rule — the duplicate delivery is the fact, the count is a fold. This is the RFC naming an outcome without regulating it: not a requirement, not a violation, just what happens (3660-3664). It is also the clearest case in the chapter of a real, user-visible state change that no protocol event corresponds to, which is exactly the class Step 1 exists to surface. Screens: inbound-only scope, the responsibility-boundary cutoff, and G1 all reject it, and the twelve-slice model has nowhere to draw it. ⚠️ FIELD HYGIENE PASS 2026-08-09 — three fields struck. message_id: RFC 5321 supplies no message identifier (§4.4's ID clause, line 3336, is optional and belongs to the receiver's Received: stamp; msg-id is RFC 5322's) and f2C8D14 is this project's minted queue_id value. Identity here is the mailbox: this is a Mailbox-rooted event and the recipient_mailbox is the only thing the RFC gives it. cause: struck because §6.1 4008-4009 and §4.5.3.2.6 3660-3664 name a single cause, the spurious end-of-data timeout, so the field could take only one value; the meaning already states it. delivered_at: struck as the event's own occurrence time — and note that the inherited example carried a second, later clock time (09:16:22) purely to suggest the gap from the first delivery, which is narrative, not payload.
