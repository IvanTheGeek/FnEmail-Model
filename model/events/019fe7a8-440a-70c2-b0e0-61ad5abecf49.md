## Notes

⚠️ The 4yz code is NOT given in this span. 451 is the conventional choice and is a GUESS, flagged as such by the original sweep and re-verified here by reading §3.3 in full — lines 1035-1045 name only 550 and 553. Do not promote it to fact without opening §4.2.1. Kept SEPARATE from the permanent rejection because the RFC's MUST is precisely that the two be distinguishable: collapse them into one event with a reply_code field and the requirement dissolves into a payload value. This is the clearest case in the chapter where the 'one event per command' target plus a single generic rejection event would have destroyed a MUST, and it is also exactly what the condemned status/phase register would have thrown out as a mere status distinction. Both screens named, neither applied.

FIELD HYGIENE PASS: struck two fields. reply_code (451) was already flagged above as a GUESS with no source in the span, which is the signal the instruction names — an unsourceable value means the field was invented; it goes on both counts, as unsourced and as the wire rendering of a decision. reason_text ('sender verification temporarily unavailable, try again later') struck likewise: that sentence appears nowhere in RFC 5321. Striking the code strengthens the note's own argument rather than weakening it — the note says collapsing the permanent and temporary rejections 'into one event with a reply_code field' would dissolve the MUST into a payload value, and with no code field on either event the MUST is now carried where the note says it belongs, in the existence of two separately named events.
