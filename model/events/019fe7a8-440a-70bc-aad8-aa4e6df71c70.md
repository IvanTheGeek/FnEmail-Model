## Notes

MERGE of four raw candidates that name one state change: TransactionBuffersReset (§3.3), TransactionBuffersCleared (§4.1), BufferCleared (§2.3.6) and StateTableReset (§2.3.6). Rejected alternative names carried here: TransactionBuffersReset, BufferCleared, StateTableReset, StateReset. UNRESOLVED TENSION worth keeping (rule 4 in spirit): §2.3.6 names TWO separable things, a buffer holding contents and a state table holding position, and 'returned to some previous state' never says WHICH previous state; merging them is this chapter's modeling choice, not the RFC's, and a facilitator should be asked. Four occasions, hence clearing_command as a field rather than four sibling events — real values: MAIL, RSET, EHLO, DATA. TransactionBuffersReset was recorded FIELDLESS by its sweep on the kit's licence that a bare state transition needs no payload; the counter-warning applies exactly here — without session_id it is an opaque label that cannot say which session was emptied — so the identity key is restored and the discarded values kept, because a model that records only 'reset happened' can never answer what was thrown away. Strength runs from bare declarative (1029-1031, no keyword at all) to MUST (2082-2083, 2455-2456). Honest objection kept from the §4.1 sweep: line 1771-1772 introduces the buffers with 'The model for this is', so they may be an artifact of the RFC's own exposition rather than domain state. Killed by every project screen — capture/decision lens, consumer test G1, altitude tiers, condemned status register — all named, none applied.

FIELD HYGIENE PASS: struck three fields. ⚠️ The paragraph above states the case for session_id explicitly — 'without session_id it is an opaque label that cannot say which session was emptied' — and it is wrong on the facts: RFC 5321 supplies no session, transaction or connection identifier at all (grep returns nothing), and f2C8D14 is this project's own minted queue-id value from commit 6acfc68, not an RFC value. The identity of the emptied session is the channel: while the session lives, the connection is what distinguishes it, and no key needs inventing. discarded_reverse_path and discarded_forward_paths struck as DERIVED — they are recoverable by folding this transaction's own ReversePathBuffered and RecipientBuffered events, which this chapter recovered for exactly that reason ('if it is never written it can never be read'), and the method forbids computed values on events because they belong in read models. The original argument that 'a model that records only reset happened can never answer what was thrown away' is preserved above and is answered by the fold, not by the payload. clearing_command survives with four real values, MAIL, RSET, EHLO and DATA, all RFC verbs.
