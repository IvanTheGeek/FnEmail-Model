# `MailDataBuffersCleared`

On completion of the DATA command the reverse-path, forward-path and mail data buffers were emptied, returning the session to the no-transaction-in-progress state.

## Data

**No data.** The method sanctions this: *"If an event has no meaningful payload beyond its identity (e.g., a simple state transition), it is fine to have no fields or just the identity key."* It also warns, of a different case, that *"An event without fields is an opaque label"* — both are recorded here rather than reconciled, because reconciling them is a later step's work, not Brain Storming's.

## Notes

RECOVERED BY THE RE-SWEEP as the DATA-specific arm of the sweeps' TransactionBuffersCleared, which merged four different clearing occasions (MAIL, completed DATA, RSET, accepted mid-session EHLO) into one event with a clearing_command field. Split out here because the fact that matters in this chapter is invisible in the merged form: the buffers are cleared on completion of the command REGARDLESS OF WHICH ARM WAS TAKEN, so a rejected message leaves the session in exactly the same clean state as an accepted one and the client may immediately start a new MAIL. The other three occasions belong to the Mail Transaction chapter and are cross-referenced, not claimed. Strength: stated as fact, no 2119 keyword. Honest objection carried forward from the sweep: §4.1.1 line 1771-1772 frames the buffers as "The model for this is" — an explanatory device, not necessarily domain state — so this may be an artifact of the RFC's own exposition. Screens: all of them — the capture/decision lens (it is neither), the consumer test (nothing reads a cleared buffer), the altitude tiers, and the condemned status register. Recorded so a later step rejects it on evidence rather than never seeing it.

FIELD HYGIENE PASS: struck both fields. session_id and transaction_id are fabricated — RFC 5321 names neither; the channel is the identity, and this event is fixed by position (the completion of the DATA command). The event is now a pure state transition with no payload, which is the case the method names explicitly as fine ("a simple state transition"). Note that fieldlessness neither strengthens nor weakens it: the standing objection is that the buffers may be the RFC's exposition rather than domain state, and no field was ever going to settle that.
