## Notes

Carried from the inherited candidate. Strength: declarative inside the branch structure of the lookup. The whole content of the event is the exchanger name and the preference 0 — nothing padded. The guard at 3850-3851 is the load-bearing half: the implicit MX exists ONLY in the absence of MX records and is never a fallback when the present ones fail; that second case is NoUsableMailExchangerFound and the two must not be merged. Precondition nobody wrote down: MailExchangerRecordWithdrawn (or never published), carried below — an empty list has two histories and only one of them is an event. Rejected alternative names: NoMxRecordsFound (a lookup result, not the state change), ImplicitMxRuleApplied. Which project screen would have killed it: the consumer test (G1) outright, since nothing in the current model consumes an MX at all. ⚠️ FIELD HYGIENE PASS: struck implicit_exchanger and preference, both as values the rule itself fixes. Line 3843-3844 says the implicit MX has 'a preference of 0, pointing to that host', so implicit_exchanger is always equal to delivery_domain and preference is always 0 — neither is an observation, both are the rule restated, and the method sends computed values to read models. This contradicts the inherited note above ('the whole content of the event is the exchanger name and the preference 0'), which is left standing so the disagreement is visible: what that note read as content is the constant the RFC supplies. Confidence is NOT downgraded — the state change is real and observed (an empty MX list came back for this domain, and the address is now bound), and what remains is the identity key alone, which is the method's expressly sanctioned shape for an event with no meaningful payload beyond its identity. This is the clearest instance of that shape in the chapter. No fabricated identity key was present to strike.
