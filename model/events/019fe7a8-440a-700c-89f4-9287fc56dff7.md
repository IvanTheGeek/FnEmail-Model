## Notes

RECOVERED BY THE RE-SWEEP — this MUST NOT appears in no inherited candidate in either arm, and it is the rule that makes the implicit-MX case an exception rather than a fallback. Strength: MUST NOT, and note that the keyword WRAPS across lines 3848-3849 ('SMTP systems MUST' / 'NOT utilize'), so any line-scoped grep of this file misses it — the inherited span notes measured five such wrapped keywords in §5-6 and this is one of them. The honored arm is a non-act and gets no event. Consequence of the violation is silent misrouting: mail goes past a domain's chosen exchangers to whatever host answers at the domain apex, with no error anywhere. Rejected alternative names: MxBypassedForApexAddress, ImplicitMxAppliedDespiteMxRecords (wrong — the implicit-MX rule is not what is being misapplied; the address RR is simply used directly). Which project screen would have killed it: the inbound-only scope and the four altitude tiers. ⚠️ FIELD HYGIENE PASS: nothing struck; no fabricated identity key was present. The three fields are identity plus exactly the two facts the MUST NOT turns on — the address that was used, and the exchangers whose existence made using it a violation; drop either and the violation is no longer visible on the event. delivery_domain and address_used take walk-scene values; exchangers_bypassed is illustrative because RFC 5321 records no instance of this violation, only the prohibition.
