## Notes

MERGE of two identically named candidates found by different sweeps (§1-2.4 and §4.4-4.5.2) plus the ABNF half the §4.1 sweep folded into RecipientAdded and flagged for recovery. MUST, and one of the very few unconditional acceptance obligations in the whole document — an exception to the FQDN rule stated three lines earlier at 714-719. 🟥 HOTSPOT under rule 12: RCPT TO:\<Postmaster> carries NO domain, so the server must supply one, and nothing in the RFC says which — resolved_domain: foo.com is the model's inference, and with several served domains the choice is genuinely undetermined. A real tension the sources leave open and this note deliberately does not resolve: §2.4 line 869 says the local-part MUST BE treated as case sensitive, while §4.1.1.3 1988-1990 carves Postmaster out as case-insensitive; the example value is written mixed-case to keep the question visible. 'every reasonable effort' (3404-3405) is NOT an RFC 2119 keyword and must not be reported as one. peer_address is kept because the point of the rule is that the sender may be any system on the Internet, including an otherwise unwelcome one. Killed by: the twelve-slice model has no postmaster path, and 'one event per command' would fold it into RecipientAccepted and lose the mandatory-acceptance fact.

FIELD HYGIENE PASS: struck one field, peer_address (203.0.113.20). ⚠️ The note above defends it — 'kept because the point of the rule is that the sender may be any system on the Internet' — and the defense is about the RULE, not about this event: the peer's address is a property of the connection, established once when the channel opened, and copying it onto a RCPT acceptance is padding. Where it belongs is the session, and while the session lives the channel is its identity, which is precisely what RFC 5321 gives instead of an identifier. resolved_domain SURVIVES with the hotspot intact: the RFC really does require the bare \<Postmaster> form to be accepted and really does not say which served domain resolves it, so the field records a genuine decision the server takes, and its example is walk-scene data rather than an RFC value — the absence of a rule is the finding, and the 🟥 marker above is what carries it. forward_path's example is now sourced to the ABNF at 1985 where the bare form is written.
