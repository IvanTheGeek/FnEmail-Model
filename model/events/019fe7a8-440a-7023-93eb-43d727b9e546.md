## Notes

RECOVERED BY THE RE-SWEEP — named as an uncarried sibling in two inherited candidates' notes and again in the §3.6-§3.7 sweep's explicit cut-for-the-cap list, and never given a slot by any of the eleven sweeps. It is the event that makes ImplicitMailExchangerAssumed reachable: an empty MX list has exactly two histories, never-published and withdrawn, and only the second is a state change. Doubtful because RFC 5321 never mentions withdrawal at all; it is inferred from the empty-list branch. Strength: none. The operational consequence is the reason to keep it: withdrawing MX records silently promotes the domain apex address to implicit exchanger, which is a routing change nobody issued. Sibling not carried separately: MailExchangerPreferenceChanged — a preference change is a re-publication and is covered by MailExchangerRecordPublished's meaning, whereas removal is not. Which project screen would have killed it: all of the scope screens. ⚠️ FIELD HYGIENE PASS: nothing struck; no fabricated identity key was present and no derived value. Both fields are the withdrawal itself — which zone, and which target left it — and neither is recoverable from the other. withdrawn_exchanger is labeled illustrative because RFC 5321 records no withdrawal, which is the same absence that makes the event doubtful.
