# `MailCommandRebuiltAfterReturnPathRemoval`

After stripping a return path, a forwarding or gateway system reconstructed the envelope MAIL command so that exactly one return path would appear in the delivered message.

| Section | Lines | Text |
|:--|:--|:--|

| §4.4 | 3268-3273 | *"a gateway from elsewhere -> SMTP SHOULD delete any return-path header field present in the message, and either copy that information to the SMTP envelope or combine it with information present in the envelope of the other transport system to construct the reverse-path argument to the MAIL command in the SMTP envelope."* |

## Notes

RECOVERED BY THE RE-SWEEP. The inherited ReturnPathRemoved (candidate 201) quoted the whole clause but modeled only the removal; 'and rebuild the MAIL command as needed' is a second state change, on a different root — the removal changes the message, the rebuild changes the envelope of the next transaction. 'as needed' makes it conditional, which is why it is a separate event rather than a field: a system may remove without rebuilding. §4.4 3268-3273 shows the same act performed by an inbound gateway, at SHOULD strength, which is where the rebuild is spelled out in full. Cross-reference, do not merge: EnvelopeReturnPathSetAtGateway and ReverseP athConstructedFromForeignEnvelope (inherited candidates 95 and 206) name the gateway-specific version and belong to the gateway chapter; the difference is that those cross a transport boundary and this one does not have to. Screens: inbound-only scope and the HELO-only charter. ⚠️ FIELD HYGIENE PASS 2026-08-09 — one field struck. message_id: RFC 5321 supplies no message identifier (§4.4's ID clause at line 3336 is optional and belongs to a Received: stamp; msg-id is RFC 5322's) and f2C8D14 is this project's minted queue_id value. Note that this event's stream_root is Transaction and RFC 5321 supplies no transaction key either — the grep for session, transaction and connection identifiers returns nothing across the whole document — so identity here is the rebuilt MAIL command itself: the reverse-path argument this event writes is what the next transaction will be known by.
