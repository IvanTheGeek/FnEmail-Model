# `GatewayDesignatedForTransportBoundary`

A route was configured — by MX record or by explicit routing — that directs a domain's mail through a host sitting at the boundary between two transport service environments, making that host a gateway for it.

## Notes

RECOVERED BY THE RE-SWEEP as the precondition §3.7 assumes and never states: gatewaying happens because someone pointed mail at a boundary host, and until that happens no rule in this chapter can fire. Marked doubtful and the doubt named: the RFC specifies no act of designation here, and "various forms of explicit routing" is deliberately vague, so the event is inferred from the routing it presupposes. Overlaps the routing chapter's MailExchangerRecordPublished, which covers the MX half generically; this card is kept because the second half — "various forms of explicit routing" — has no other home and because it is the moment a host acquires gateway permissions it did not have, which is the classification consequence AddressRewrittenByGateway also turns on. If a facilitator merges the two, keep routing_mechanism, since MX and explicit routing are different acts by different parties. Strength: NONE, descriptive. Rejected alternative names: ExplicitRouteThroughGatewayConfigured, TransportBoundaryHostAppointed. Which project screen would have killed it: the four altitude tiers would file it Infrastructure; the twelve-slice model has no configuration actor at all.

FIELD HYGIENE PASS: nothing struck — no message_ref, no f2C8D14, no reply code. This is the third clean record in the chapter, and the reason is instructive: it is the one event whose subject is durable configuration rather than a message in flight, so the sweep had a real identity to hand (the host-and-domain pair that IS the route) and did not have to invent one. routing_mechanism verified at line 1534, which reads "SMTP transport service environment, MX records or various forms of". Confidence stays doubtful for the reason already recorded — the RFC specifies no act of designation — and the clean field list does not change that.
