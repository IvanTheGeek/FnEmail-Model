## Notes

RECOVERED BY THE RE-SWEEP, from a gap the inherited AcceptedMessageLost (candidate 273) named in its own notes but had no slot to fill: 'The preventive event nobody wrote down is AcceptedMessageCommittedToStableStorage — the commit that makes the MUST NOT achievable is implied by the whole paragraph and stated nowhere.' Confirmed against the text: §6.1 3965-3967 forbids losing the message to a host crash, which is unsatisfiable unless something durable happened first, and the RFC never says what. This is the honored arm of that MUST NOT, and it is the event a real implementation actually emits — a spool write, a fsync, a queue insert. ⚠️ Rule 2: the 'must' at line 3964 is lowercase and therefore not an RFC 2119 keyword; the genuine MUST NOT is the sentence after it. Ordering relative to ResponsibilityForMessageAccepted is a live modeling question the RFC does not settle — commit-then-reply is the only ordering that honors 3965-3967, but the spec states neither the ordering nor the commit. That is a 🟥 under rule 12. Screens: the four altitude tiers would file it as Infrastructure and drop it; G1 would ask what consumes it. ⚠️ FIELD HYGIENE PASS 2026-08-09 — two fields struck. message_id: RFC 5321 supplies no message identifier; §4.4's ID clause (line 3336) is optional and belongs to the receiver's own Received: stamp, and msg-id is RFC 5322's. The example f2C8D14 is this project's minted queue_id value. Identity here is the message the server has just accepted, which the session itself identifies — this event can only occur inside the window opened by ResponsibilityForMessageAccepted, on the same channel. 🟥 SHARPENED BY THE STRIP: an implementation's real commit DOES mint a durable handle (the spool name, the queue id), and that handle is what a later Received: ID clause would carry — so the absence of an identifier in RFC 5321 and the presence of one in every real implementation meet exactly here. committed_at: struck as the event's own occurrence time. committing_host survives because §4.4 records the acting host as trace data (From-domain 3317, By-domain 3319).
