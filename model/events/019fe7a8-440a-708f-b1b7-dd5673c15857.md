## Notes

Merged TimeoutPolicyConfigured (§3.8 sweep) and TimeoutValuesReconfigured (timeout sweep). Rejected alternative names: TimeoutValuesReconfigured, TimeoutMinimumsAdjusted. Reached from §3.8 by the spec's own cross-reference: the close is licensed 'as specified in Section 4.5.3.2', and that section makes the limits reconfigurable, which makes reconfiguration an event over time. Without it, every timeout event's limit has no origin. A precision the inherited candidates blurred and that a future reader would otherwise re-derive: the 'easily reconfigurable' SHOULD sits in a paragraph addressed to CLIENTS — it opens 'An SMTP client MUST provide a timeout mechanism' — while the server-side 5-minute figure at §4.5.3.2.7 is a bare SHOULD with no reconfigurability language at all, so extending 'easily reconfigurable' to the server side is an inference, not a quotation. The seven named minimums are SHOULD floors an administrator may raise but not lower. Screens: the inbound-only scope and the altitude tiers, which place configuration at Infrastructure.
