## Notes

RECOVERED BY THE RE-SWEEP — the violated arm of §7.4, which the merged list carried only in its honored form (AddressBookEntryUpdated). §7.4's entire content is one requirement and one named failure, and the failure is the state change worth modeling: an address record is now poisoned, permanently, by a party the client never identified, and every later message to that correspondent goes to the attacker. Strength: a LOWERCASE "should" at line 4288, with NO RFC 2119 keyword — §7 is unusually weak normatively for a section this consequential, and anyone tiering these events on normative strength must read the case, not the word. This is the natural hotspot of the chapter (rule 12): RFC 5321 offers the client no mechanism at all for being certain of a server's authenticity, so the requirement is unsatisfiable within this specification. Not merged with AddressBookEntryUpdated: the same write with a different provenance is arguable, but the distinguishing fact — that no authentication preceded it — is not recoverable from the other event's payload, and §7.4 exists solely to name it. Rejected alternative names: ForgedAddressCorrectionAccepted, PoisonedAddressBookEntryWritten, MailReroutedByManInTheMiddle. Screens: responsibility-boundary cutoff and inbound-only scope; the twelve-slice model has nothing on the client side at all.

⚠️ FIELD HYGIENE PASS (fields and notes only): struck one field, reply_code (251) — the rendering of a decision, and §7.4 rfc5321.txt:4286-4288 names 251 and 551 together without distinguishing them, so the code adds nothing the event does not already say. announcing_server KEPT, and the reason is the hotspot restated at field level: §7.4's whole content is that this party's identity was never established, so the field can only ever hold a CLAIMED domain, never a verified one. The value is what the peer said, not what the peer is — the project's own convention already has a name for that shape (`claimed_domain` in the walk), and adopting it here would be a rename, which this pass does not do; recorded for a later step. Sourced: announcing_server at rfc5321.txt:4886, the RFC's own greeting from foo.com; corrected_address composed from the RFC's Green (4884) and xyz.com (1940), the address itself absent from RFC 5321. The struck reply_code leaves the event with two fields that are precisely its two halves: what was written, and who was believed.
