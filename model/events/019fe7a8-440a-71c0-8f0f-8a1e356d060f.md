## Notes

RECOVERED BY THE RE-SWEEP. Candidate 224's notes named it as a merged sibling and it was never given a row — exactly the loss the cap produced. The same wire fact is a violation for the sender and a mandatory tolerance for the receiver, which is why it must not be modeled as one event: ReplyTextOmitted (server, SHOULD NOT) is the emission arm and is folded into this note rather than given its own row for budget; split it out if peer-conformance monitoring is ever modeled. Strengths, all in two sentences: SHOULD that the client be prepared, SHOULD NOT that the sender do it, MUST that any text including none be acceptable — the MUST at 2614 is the strongest of the three and is easy to miss because it sits after a parenthesis. trailing_space_present is a captured fact, not a derived one: the RFC names both shapes and a strict parser distinguishes them. Screens: the inbound-only scope kills it outright (client actor).
