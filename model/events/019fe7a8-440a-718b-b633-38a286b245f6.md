## Notes

The phrase 'domains to which the host expected to be able to relay mail' names a set with a current value; sets with current values are built by events, and this is the one that builds it. No modal verb governs the authorizing act — the RFC only says verification against the set MIGHT be part of apparent validity — so this is inferred, hence likely. Kept distinct from RelayPolicyConfigured even though both concern relay destinations: this set is consulted by VRFY/EXPN when deciding whether to answer 252 for an address that cannot be verified in real time, not by RCPT when deciding whether to relay. Same-looking, different consumer; do not merge. A CrossRelayVerificationDeclined event was considered from 1362-1364 and dropped by the original sweep as too thin. Screens: the HELO-only charter and the responsibility-boundary cutoff both kill it. FIELD HYGIENE: nothing struck; the two domains are the identity pair and nothing else was carried, which is the method's 'identity key plus nothing' case and correct here. No session, transaction or connection key was present; RFC 5321 supplies none, and the set this event builds is keyed by nothing but the two domain names.
