## Notes

RECOVERED BY THE RE-SWEEP. Strength: none — descriptive. Carried because it is the one case where a single label IS an FQDN, which makes it lexically indistinguishable from LocalAliasAppearedInTransaction and separable only by DNS; that collision is exactly why the RFC calls the FQDN requirement 'particularly important' here, and it is a 🟥 for any implementation that screens unqualified names by counting dots. Doubtful because the RFC describes the form without ever recording an occurrence. RFC 5321 gives no top-level-domain example anywhere, so under rule 8 the example uses museum, a real top-level domain, rather than a placeholder. Rejected alternative names: SingleLabelDomainUsed (wrong — it conflates this with the local-alias case, which is the whole point), BareTldAddressAccepted (asserts an acceptance the span does not license). Which project screen would have killed it: none specifically; it simply has nowhere to live in the twelve-slice model. ⚠️ FIELD HYGIENE PASS: struck delivery_domain as a derived value — for a bare top-level-domain address it is the forward-path's local part removed, with no case-folding or dot-counting decision left to make, so unlike DeliveryDomainLexicallyIdentified there is no state change in the split. Identity is the forward-path itself. The remaining example stays honestly labeled illustrative: museum is a real top-level domain but RFC 5321 supplies no instance of this form, and that absence is the reason the event is doubtful.
